# D102 — A site-corr data pin becomes disasm-verified only by the data-bytes route
id: D102 · group: D · status: active · tags: symbols,pins,data,candidate · origin: Phase 3.3 T8 binding (filed 3.5 T11) · added: 2026-10-30

## Text

A site-corr data pin becomes `disasm-verified` (source `proto-pdb-public+site-corr+data-bytes`) only when retail initialized bytes at the pin VA equal default.exe bytes at the one PDB public of that name over the S_GDATA32/S_LDATA32 TPI size (vtables: the 3.1 slot extent), pointer fields (proto .reloc offsets) agree by accepted name at the retail target, and the span carries identity (one non-zero byte or one agreeing pointer); else it stays `site-corr` with one reason. Text: docs/evidence/correspondence.md "## Data byte route (3.3 T8)".
