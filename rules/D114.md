# D114 — disasm-verified is written only when the retail target's own bytes were checked (M18's checks); globals and failed checks carry site-corr unless D113 writes corr-verified or D115 near-corr; candidates never accepts site-corr
id: D114 · group: D · status: active · tags: naming,pins,symbols,ratified · origin: 4.2 T4 review, developer 2026-11-02; amends M18 · added: 2026-11-02

## Text

A symbols_pin status written as `disasm-verified` means the retail target's own bytes were checked (callee: masked bytes equal plus outgoing targets agreeing by name, a callee under 8 unmasked bytes needs one agreeing target; vtable: every slot passes; string literal: bytes equal; `__real@`: the value in bytes). A global, a vtable without those bytes, or a failed check carries `site-corr`, unless a D113 route writes `corr-verified`, or `near-corr` under D115 for a called function. Candidates never accepts `site-corr`.
