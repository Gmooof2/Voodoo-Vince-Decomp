# M20 — D46 reading: a string literal a function references may be written as a literal, text copied exactly from retail; no other game text or data in tracked files
id: M20 · group: - · status: active · tags: firewall,matching,ratified · origin: developer decision 2026-10-28 (3.3 T4 question) · added: 2026-10-28

## Text

Reading of D46 for string literals (developer, 2026-10-28, 3.3 T4 question): a string literal that a function in `src/` references may be written in the source as a literal, its text copied exactly from the retail bytes at the referenced address (the gate's bytes layer proves it). No other game text or data enters a tracked file: no tables, byte arrays, assets, dumps or strings a function does not reference. The address-label form (`s_<va>` in `config/retail/symbols_pin.txt`, 1.4 T9) stays valid; existing labels are not converted outside a review. Generated docs keep masking `??_C@` names and string labels.

## Why

Retail objects name many literals `??_C@...`, a name the compiler builds from the text, so only the exact text reproduces the relocation (the creationFunc rows' `__FILE__` paths, 3.3 T3/T4). PROJECT_CONTEXT.md lists copyrighted bytes as files, executables, objects and databases; literals copied from retail are evidence, not invention (D78). The public release (3.6) discloses them alongside the PDB-derived names.
