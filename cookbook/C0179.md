# A row leaving a batch needs its source guarded; a wrong-bytes row also fails relink

- Taking a failed row out of `config/matched_set.toml` is not enough when its source compiles: the next gate fails `*objects* extra` (`matched_set.py:331-346`, membership per unit). `tools/match_finish_batch.py` wraps it in NON_MATCHING and re-runs the full gate.
- Do not treat "a global failed" as "stop" while a row also failed: a wrong-bytes row fails `relink` too (`REFUSED ... not a COMDAT .text section`). Leave the row, let the next gate decide; stop only on a global with no failed row, or a failed row outside the batch.
- `last.json` is not written on the gate's early returns (lock, refusal): check its `date` and row set before trusting `passed`.
- `commit_task.sh` refuses an empty stage (rc 1) and a failed commit leaves its paths staged, where the next task's commit would take them: `git diff --quiet` first, `git reset -q -- <paths>` after.
- Controls: a real gate in a scratch clone works with `derived/` and `config/local_paths.json` copied in and `core.hooksPath=githooks`; drop matched rows from the clone's list and re-add them as the batch. Use `shutil.which("bash")` in the harness too (C0170).
