# cl 13.10 compile-time size assert: negative-array typedef, C2118, zero symbols

## When
A struct layout from the PDB (TPI, C0023) must be pinned in source; cl 13.10.3077 (VS .NET 2003) has no `static_assert`
(C or C++).

## Technique
- `src/include/decomp.h`: `DECOMP_SIZE_ASSERT(type, size)` =
  `typedef char DECOMP_PASTE(decomp_size_assert_, __LINE__)[(sizeof(type) == (size)) ? 1 : -1]`, two-level paste so
  `__LINE__` expands. File scope, right after the struct. Works in `.c` and `.cpp`; no `namespace {}` (C refuses it).
- Wrong size: cl exit 2, code `C2118` (negative subscript), caught by `msvc71.compile_one` CODE_RE.
- Right size: `coff_info.py` output of the obj identical with and without the assert (14 lines, the function symbol
  only): no symbol, section or reloc, so the gate's `*objects* extra` check is unaffected.
- C units: `struct S` needs its tag unless typedef'd; C++ accepts `S`.
- Units include it by relative path: build.py passes no `/I`.

## Evidence
1.6 T4.c1 (commit 9b7ed16) and the expert's re-run (scratch `.run/1.6/size_assert_check/run.py`, not kept): /O1 /Oy, a 3-int struct,
variants none / 0xC / 0x10, both languages; 0x10 -> C2118 both; none vs 0xC coff_info equal both.
