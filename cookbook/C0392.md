# Byte-identical parallel self-test: controls in worker processes

Done in 5.4 T5.c2 (gate_controls.py). The serial run took 179 s; the parallel run takes 60 s and its stdout is byte-identical.

- Use processes, not threads: controls monkeypatch modules and env and undo in `finally`.
- The parent keeps the run lock and the positive run. Workers get a hidden flag that returns before the lock is taken.
- Each worker captures its stdout per control (the parent's encoding and errors, `\r\n`) and writes length-framed blocks to a file. The parent writes each block's raw bytes to `sys.stdout.buffer` in CONTROLS order, flushing `sys.stdout` first.
- A crashed worker, an rc != 0, a short or garbled file, a missing control, or bytes outside the blocks all count as DID NOT FAIL for every control of that worker (D26). K is always len(CONTROLS).
- Scratch: repoint each fixed scratch path per worker, in-process (`_phase_run_dir`, `matched_set.SCRATCH`, `provenance_lint.LOCALS_SCRATCH`, relink's link tag `gate` becomes `gate.w<K>`, else workers write into the positive run's `derived/relink/.../link/all=gate`). Keep any path that appears in printed output identical (control dirs `<phase>/gate/controls/<name>`): per-worker roots gave 712 golden diff lines.
- Sizing: N = clamp((free_mb - 6144) // 384, 1, CAP). 384 MB is one worker's measured free-memory drop. Wall time was flat at N 4, 6 and 8 because the parent's positive run is the long pole (its audit layer takes 56 s), so CAP = 4.
- Teeth: forcing a control's expect to False makes the self-test exit 1. A True expect still "fails as expected" when rc != 0 (the runner's `ok and rc != 0`).
