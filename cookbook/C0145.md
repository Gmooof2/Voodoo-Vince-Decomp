# Inline-elsewhere emitters, ??_G by delete, vptr-store order, std::string operator=, listing-only ledger trap

- Inline function retail emits in this unit while other units emit it as COMDAT: an out-of-line definition passes match_one but the gate's relink fails LNK2005 (3.4 T4.c1 TextureManager::GetDefaultTexture vs MoviePlayer.obj, Sprite.obj). Keep it inline in the class; force emission with an address-taking `// !FAKE:` emitter function plus an `[[emitter]]` row (`matched_set.py add --emitter`, C0104, C0122).
- Non-virtual scalar deleting dtor `??_G...QAEPAXI@Z`: emitted by an emitter doing `delete p;` (AreaStats, Onion.obj).
- One inline template member: explicit instantiation of that member alone (`template ResourceHandle<T>::ResourceHandle(const ResourceHandle<T>&);`) emits it; no emitter row needed.
- Ctor with float member stores: separate `x=0` stores schedule the vptr store after the first fstp; the PDB inline `Vector3::Zero()` gives retail's `fldz; mov [eax],vtbl; fstp` (81.8 -> 100, FFlyWind). Such ctors still meet the vtable relink wall (C0123) until vtable data pins exist (C0129).
- `const char*` assigned to a std::string member on the opaque basic_string shell: an inline `operator=(const E* p) { return assign(p); }` reproduces retail's `assign` reloc.
- Trap: `match_one --listing` runs are ledger kind `listing`; `--table` refuses a matched row with no plain `attempt` run: do one plain run after listing runs (wmemset).
