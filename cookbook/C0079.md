# Whole-image substitution traps: unreferenced data COMDATs, unreachable inline duplicates, CRT names

Context: T4's route (C0077) scaled to every matched function (18 units) in the whole-image relink (2.3 T6, T6.c1, tools/relink.py `_all_ours`, `check` no args).

- Unreferenced data COMDATs in our object: cl emits header statics (SoundNode.obj: 43 `std::_Iosb`/`_Locbase` static-const `.rdata` COMDATs) that no reloc targets and that `/OPT:REF` drops. They are not image data; asking their VA by name refuses. Rule: skip a COMDAT data section that is not associative (Selection != 5) and no reloc in our objects targets.
- Inline copies defined by both our object and a cut original (MoviePlayer.obj `??0?$ResourceHandle@VTextureResource@@@@QAE@ABV0@@Z`, `?GetDefaultTexture@TextureManager@@...`): when every one of our definitions is an unreachable COMDAT and no object of ours references the name, rename the cut definition and its references `<name>@va_<va8>`; our copy goes unreferenced and REF drops it. Two of OUR objects defining the same inline COMDAT (Selection 2) is fine for LINK.
- CRT names with no reloc site still need a definition: `__fltused` (undefined in every object using float, no reloc) -> LNK2001 when dropped; same as `.sxdata`'s `__except_handler3`. Resolve via a pin with evidence, never invent.
- Verifier lock: a scratch script importing relink before `gate.main` fails the lock ("unlisted module"); import it after the gate.
- Our objects vs the gate build: whole-file sha256 differs (TimeDateStamp, `.debug$S` path); compare non-debug sections + symbol table instead (18/18 equal).
