# Splitting code out of a script that runs as `__main__`

Problem: `gate.py` runs as `__main__`. Moving its self-test controls into `gate_controls.py` and writing `import gate` there loads gate.py a second time as module `gate`. That copy gets fresh globals (a new pycache prefix, its own `_tool`, `RUN_LOCK`), so every control that monkeypatches a gate global patches the copy, and the running `_core` never sees the change.

Move:
- The caller passes itself in: `gate_controls.controls(sys.modules[__name__], config)`.
- The callee binds once: `_bind(gate)` sets `G = gate` and copies the names the controls read (`GATE_NAMES`) into its own globals.
- Patches go to `vars(G)[name]`, never to `globals()[name]`. A patch on a name the caller calls through the new module (e.g. `controls`) goes to that module's globals. The undo restores both.
- Import the new module only on the path that needs it (inside `main`), and put it in the verifier lock's LISTED. Otherwise the lock-imports layer flags it.

Proof: every monkeypatch control (relink-error, prov-refused, annotations-error, lock-imports, gate-lock) still fails at its own check, and the self-test's stdout is byte-identical to the golden (C0389).
