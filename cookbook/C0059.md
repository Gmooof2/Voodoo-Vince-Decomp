# Name an unmapped retail callee from the prototype PDB (no invented name, D78)

When a retail function calls/jumps to a VA absent from symbols.txt (`FUN_xxxxxxxx`, candidates `reloc: unresolved`):
1. `grep <va> derived/proto_map/retail-xbe/near_identical.jsonl` (or functions.jsonl `candidateVA`): a near-identical
   row gives the PDB name and protoVA (symbols.txt takes identical rows only, so these are missing by construction).
2. Cross-reference chain: decode the rel32 CALL/JMP (E8/E9) in the PDB-named caller in both binaries. The prototype
   is a PE (`default.exe`, protoVA is a PE VA: parse the PE section table, not xbe_info), retail via
   `xbe_info.parse_xbe` + `va_to_off`. Same caller offset, target = the PDB function in proto and the VA in retail.
3. Decorated name: `derived/pdb_info/default/publics.json` (off + 0x400400 = protoVA for seg 1 in this PDB).
4. Size: next retail function start minus VA, against Ghidra applied bodyMax; print addresses only (D46).
5. Pin it: `config/retail/symbols_pin.txt` `func 0x<size> <decorated> <source> disasm-verified`, evidence in
   docs/evidence/compiler_pin.md. Pins reach gate, candidates and the delink's ApplySymbols (2.1 T4).
Example: GameOptions::RestorePreviousState 0x125FC3 `jmp 0x125F98` = `?Set@GameOptions@@QBEXXZ` (2.1 T4).
