# Split a merged Ghidra body at a pinned func; absorb a FUN_ fragment on grow

When: one Ghidra function holds two pinned funcs (cut-body-merged row; `inside` in the ApplySymbols summary), or a grow (C0105) is refused because a `FUN_` sits inside the pin range.

Split (tools/ghidra_scripts/ApplySymbols.java, 3.2 T2):
- Condition: func line at VA, sized, accepted status (unverified|verified|disasm-verified; never site-corr/boundary), VA inside function C, C's entry has its own sized accepted line, and C.entry + C.size <= VA.
- Act: set C's body to [C.entry, C.entry+C.size), createFunction(VA). Null result -> restore C's body, count `inside`.
- Print `ApplySymbols: split <C> at <entry> for <name> at <va>`; counts as `created` (delink.py check: renamed+created+labelled == lines) and `split S`.
- Overlapping proto sizes (container pin end > VA, e.g. ??1OptionsMenuGuts 0xE13B7 0x73 over ??1PropellerMain 0xE1418) stay `inside`: correct refusal.

Absorb on grow:
- Remove the overlapping o only when: o is DEFAULT-named, no func line at o's entry, o's body inside [a, end], f's line accepted.
- Evidence before trusting it: proto proc length == pin size, masked-equal proto vs retail over the pin size, no PDB proc/public at proto + (o - entry), and the only rel32 ref to o lies inside the pin (heap trio, ___FrameUnwindToState: E8 from inside) or no refs at all (GasPump::Message, TimerEvent x2).
- If any check fails -> it is a real neighbour: pin it per C0103 instead.

Control (C0105-style, scratch pin lines then removed): a container ending mid-instruction (D3DDevice_Clear xbsymdb 0x2C9 vs Ghidra 0x39F) makes createFunction return null -> restored, `inside`. A scratch container 0x11178 0x18 + 0x11190 0x2A split cleanly.
