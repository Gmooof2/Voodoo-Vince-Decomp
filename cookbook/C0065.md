# C0065 — opt control: /O2 discriminates float-literal/float-arg functions; /Oy- only with esp arg reads
tags: msvc,opt,control,o2,oy,negative-control,match_one · date: 2026-10-26 · phase/task: 2.2/T4 · origin: T4.c1 controls

# opt evidence: /O2 discriminates where /Oy- cannot (extends C0062, C0063)

- 2.2 T4: in three /O1 /Oy units (DoorStorageRoom, LoadScreen, SwampInput) the `--control "/O2"` run fails (30.0, 54.375, 80.0). /O2 uses integer pushes of float literals, `mov [esp-4]` with tail jmps, and integer float copies.
- `/Oy-` fails only when the body reads a stack argument through esp (SetGameTime gets `push ebp; mov ebp,esp`). Functions with an unused argument, or a call with no argument reads, keep no frame and pass under /Oy-.
- `/Od` fails everywhere and only shows "optimized". For a leaf with a call and no float literal (Swamp::MarkSceneRenderingStartTime), /O2 passes, so O1 vs O2 stays open. The opt comment says so.
- Use: prefer an /O2 control on any function with a float literal or a float argument. It separates O1 from O2, which /Oy- and /Od cannot.
- Git Bash: run controls with `MSYS_NO_PATHCONV=1` (C0027), or match_one refuses `/O1 /Oy-` as a path.
