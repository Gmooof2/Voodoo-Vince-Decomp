# Read a PDB 7.00 in pure Python and cross-check it with llvm-pdbutil

Proven: T6 (phase 1.2), `tools/pdb_info.py`, on cl 19.51.36260 fixtures and clang-cl/lld-link PDBs.

- DBI header (64 B): `machine` is the u16 at offset **58** (flags u16 at 56, 4-byte pad at 60), not 62. A wrong offset reads machine 0x0.
- Module symbol stream starts with a 4-byte signature; records follow (u16 len, u16 kind).
- Compile record: the first S_COMPILE3/S_COMPILE2(_ST)/S_COMPILE in the module; none -> report `missing`, never fLTCG 0. S_COMPILE has no fLTCG bit: report `n/a`.
- Current MSVC: our objects carry S_COMPILE3; /GL sets flags 0x2400 (fLTCG bit 10 + securityChecks), plain 0x2000. CRT/`* Linker *` modules mix S_COMPILE2/3, fLTCG 0; `/LTCG` adds a `* CIL *` module.
- DIA-style pair check: RSDS has GUID + age only; compare info-stream GUID and DBI age. Signature only matters when no GUID is passed.
- llvm-pdbutil `dump --modules`: only the first `Mod NNNN |` line is indented; match on stripped lines.
- MSVC build dirs hold `vc140.pdb` (the /Fd compiler PDB) beside the link PDB: pick the PDB by the exe's name.
