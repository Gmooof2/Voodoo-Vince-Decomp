# Comment-only source edits the provenance lint still refuses

`git diff` shows comments only, objdiff is green, yet the gate's `provenance` layer fails. Two cases (3.6 T10.1):

- Text edit on a `// !FAKE:` line: `fake_pairs` sees old line removed. Unless a code line of the same FUNCTION body changed
  since `merge-base HEAD @{u}`, it reports `fake-diff ... removed`. A rewording is a removal to the check.
- New `// NAME: proto-pdb:...` line: the lint resolves the next code line's identifier, not the row's name. Unqualified
  `vector<X>::resize` inside `namespace std`, a scoped return type (`vector<X>::size_type vector<X>::size`), and a
  scaffold with no `[[emitter]]` row all fail, even with a correct map row.

Check first: after any edit to a label or a new NAME line, run `PY tools/provenance_lint.py` or the gate, not only
`annotations.py --check`. The two tools disagree on what a NAME line needs.

The check is locked (`verifier_lock.py`): change it only through a planned task with a self-test control; never pass it
with a block comment or an altered tag spelling.

Fixed 4.1 T4: a reworded `// !FAKE:` label and both NAME cases now pass; a removed label and a wrong name still fail (controls `prov-fake-reword`, `prov-name-ns`). What stays true: run the gate after a label or NAME edit, not only `annotations.py --check`. A scaffold name absent from the PDB still fails: it carries no FUNCTION line until its row matches.
