# Classify a near row's unresolved reloc targets before drafting (vtable, __real, ??_C, local static, callee)

Context: 5.4 T8.c2, Critter.obj's 9 reloc rows (90 B to 2915 B); none drafted, all walled with named targets.

Steps per target (candidates.jsonl / next_candidates.md list them):
1. `va_dis.py dis <rowVA> <size> <protoVA>`: align the retail and proto lines that use the target; read the proto operand.
2. `va_dis.py sym <protoVA>`: the proto PDB public at or below it. Exact hit = the name (vtable `??_7X@@6B@`, callee,
   `??_C` string). "public + offset": check that public's size first; a 4-byte pointer + 0x38 is NOT a member (C0144
   does not apply): it is a function-local static (S_LDATA32 in the PDB), or its guard.
3. Floats: `va_dis.py vt <va> 1` prints the stored dword: the name is `__real@<hex>`.
4. A target with no proto public (e.g. a local static's atexit dtor thunk) needs the compiler-name route.
Critter's .rdata: retail 0x1ED9xx = proto 0x5D65xx (delta 0x3E8C00).
Routes (all pin work, outside a matching task): vtable data pin, function pin from the proto PDB public, `__real@` pin,
`??_C` pin (multi-literal rows still hit the C0133 relink wall), PDB local-static names.
Rule of thumb: do not draft a large reloc row before every target has a route; drafting cost buys nothing at relink.
