# STL generator in opaque-std units, fold-alias template argument, char_traits intrinsics (4.3 T12 W1)

- Opaque `namespace std` unit (C0090) that already holds the verbatim VC 7.1 inline body: the gen_stl instantiation line alone matches; no `<set>`/`<map>` conversion (SwampScript `multiset::insert` 0x000AC383, T12.c2). Converting is only needed when the body is absent; ProfileBar was converted (`<string>/<vector>/<map>`, `--callees` decl-only `_Lbound`, `insert(it,v)`, hand decl-only `vector<uint>::erase(it,it)` stops `_Copy_opt`/`_Destroy_range` emission, T12.c3).
- Fold VA named in the delinked retail object only by another unit's alias: objdiff pairs by name, so instantiating the unit's own type gives bytes match but objdiff `None`. Instantiate the alias's argument, declared minimally from the PDB (ParticleManager `pair<const string, FontManager::LangInfo>` ctor 0x000B8077, T12.c6).
- Static member of a full specialization (`char_traits<char>::copy/assign`): gen_stl refuses static rows; `template char* std::char_traits<char>::copy(char*, const char*, size_t);` emits it out of line on cl 13.10 (T12.c4).
- Retail inline memset/memcpy forms: `char_traits::assign` (BeepLib) matched with a per-file `#pragma intrinsic(memset)` (C0181); `char_traits::copy` (Init, 0x00011000) needs unit opt `/O1 /Oy /Oi` (pragma memcpy had no effect, C0231): 2.5 without, 100 with.
- gen_stl `--symbols-from` does not skip `#` comment lines (rc 2): feed it mangled names only.
