# Per-component stores instead of Set fix a call's lea/push schedule; y=0 folding needs no call between store and length

- A `lea/push` pair for a call scheduled differently from retail: store `v.x`, `v.y`, `v.z` one by one instead of `v.Set(...)`, with a named stand-in for the product (`float v3 = sinf(a) * speed;`, C0332). FFlyEllipseSurf::Spawn 0x0006F479 matched (was labelled wall-schedule); with v3 inside `Set` only 95.80.
- cl folds `y*y` for y = 0 in a length only when no call sits between the y store and the length (`pos.Set(pos.x, 0.0f, rand)` + `LengthSquared()`).
- Initialising a Vector3 through a ctor or `Set` with `rand(-p, p) * 0.5f` args hoists both negated bounds (inline-argument temps) and keeps the scale alive past its last product.
- Earlier wall-regalloc / wall-schedule labels on these Spawn rows came from statement order, not register allocation: a label without a mechanism is no wall.
