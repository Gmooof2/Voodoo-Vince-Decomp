# Small vector accessors at fold VAs: caller scan before listing; real-header _Xlen via __assume(0); placement new beside debug new (4.3 T12 W5)

- Tiny vector accessors (`size`, `capacity`) sit at fold VAs shared with other element types. Before listing, scan our relink objs (`derived/relink/<pin>/link/all=gate/obj/ours/*.obj`, or a recent build dir) for undefined externals to the OTHER aliases: any hit means relink refuses "lies in a replaced range" (C0233). Retail delinked callers using the row's own name do not block. Seen: SRM `vector<Vector2>::size` (SwampGatorNode calls the Override alias), SwampScript `vector<SaveLoadVar>::size` (Music calls the Overlay alias), BubbaGator/Settings `vector<Param>` capacity/size (FrontEndUI calls the `vector<string>` aliases, declared only there since T12.c24). Lift = C0233 fix 1 in the caller unit (verbatim body so its alias COMDAT merges), then unguard.
- Real-header unit: `__declspec(noreturn)` cannot be added to a decl-only specialization of the header's `_Xlen` (C2381). Write the row as a hand explicit specialization of the header body with `_Xlen(); __assume(0); // !FAKE` (Oven `deque<Vector3>::_Growmap` 0x0007B602, T12.c30). Opaque-std units use the C0237 declaration (HUDUI `vector<AreaStats>::_Buy`, T12.c28).
- C0233 fix 1 in a unit with a debug `operator new(unsigned,const char*,int)`: also declare the VC 7.1 placement `operator new(unsigned, void*) throw()`, else C2660/C2661 (VinceSpring `_Construct<HeightSample>` 0x000AE5C1, 23 B byte-equal, T12.c30).
- Element sizes differ per unit for one PDB name (LevelLoader::Slot 0x8C in SignTrolley, 0xA4 in FrontEndUI's code): read retail's `idiv`/`imul` constant before declaring (T12.c29).
- Decl-only named `copy` (fold 0x000B7E9C) stops `vector::erase` emitting an unnamed `_Copy_opt` (ParticleManager, T12.c25); a gen line can replace an older decl-only member specialization when the callers still match.
