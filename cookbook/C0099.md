# Run clone commands without leaking config values

Problem: commands run in a scratch clone at `<game_dir>/clone-*` need the clone path, and tool output prints absolute
paths, the boot path and other config values (D46). Typing the path, or letting the output through, puts the values
into the auto-committed journal and the logs.

Move: one scratch wrapper, `.run/<phase>/<task>/inclone.py [--wc] <cmd...>`:
- resolve the clone dir from `tools/vv_inputs.load_config` (`--wc` = repo root); never print it
- `subprocess.run(cmd, cwd=dir, capture_output=True)`
- replace every config string value, and its resolved-path forms (`\`/`/` variants), with `<key>`; do longest values
  first and match case-insensitively
- print the redacted stdout and stderr and pass the exit code through
Run it as `bash tools/run.sh <name> -- PY .run/<phase>/<task>/inclone.py <cmd...>` so the log holds only labels.

Used: 2.6 T7 (every audit, deploy-rehearse and pitfall run from clone-2.6b and the WC; nothing leaked, the pre-commit audit passed).
