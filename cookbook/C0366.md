# Recount capped hit lists inside the tool, self-checked on the uncapped rows

`functions.jsonl` stores at most `HIT_CAP` (32) target VAs per prototype row, so k (bodies that are Ghidra entries) is
unknown for every row at the cap (5.2 close: 2,386 of 3,643 ambiguous rows). To get exact k without touching the
derived file or comparing each row against every entry (27 M masked compares):
1. Rebuild the row's mask exactly as proto_map does: `mask_proc(pb, P, img.plo, img.phi)` plus the `.reloc` sites
   inside the proc (`img.prelocs`), then `segments`, `anchor`.
2. `find_matches(secs, pb, segs, anc, cap=None)` over the retail exec sections (built as proto_map.py:444-445 from
   name_sites' `Images`), and intersect the hits with the entry set (Ghidra entries plus `config/gap_functions.toml`).
3. Self-check before trusting it: every row with `hits < HIT_CAP` must reproduce its `targetVAs` set exactly; print
   it as a checked sum line (`recount: rows under cap N agree N`), FAIL otherwise.
Result at 5.3 T1: 43.8 s for the whole tool; k changed on 2,356 of 2,386 capped rows; ruled classes moved
(k1 37 -> 41, D115 575 -> 710, D113 18 -> 36, caller-xref 62 -> 71, none 2,951 -> 2,785). Any sizing read from the
capped list undercounts bodies and misclasses rows.
