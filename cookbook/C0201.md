# match_finish_batch runs in the foreground; a draft's parameter names must be PDB locals before the finish

- 4.3 T4 B1: `match_finish_batch.py` as a background shell (`run_in_background`) was killed mid-gate by the harness's low-memory reaper (free ~4.5 of 32 GB, coders idle). The rows it had added to `config/matched_set.toml` were gone afterwards; src and ledger stayed dirty; a rerun was not refused.
- Run it in the foreground through `tools/run.sh` with timeout 285000: one gate at 623 rows took 74 s, the whole finish 83 s. A batch that drops rows runs a second gate: split it into one foreground call per gate rather than backgrounding (house rule 9).
- Start no coder while a finish's gate runs.
- Same batch: `match_one` passed `TimerEvent(unsigned int timerId)` but the gate's provenance layer failed `locals`: the PDB names the parameter `id` (`PY tools/pdb_types.py locals 'Class::Method'`, the demangled form; the mangled name says "not found"). A red global with no failed row aborts the batch whole (`restored 2 files`), so check names before the finish: `pdb_types.py locals` for every parameter and local of a new draft.
- B2: a vptr-storing ctor/dtor row (C0123 screen) passed match_one but the gate's relink failed `REFUSED our <unit>.obj: external ?<virtual>@<Class>@@... does not resolve by name` (an unnamed vtable slot): `??0FrontEndUI` (UpdateAnimation@SwampSceneNode), `??1LoadScreen` (EndOfTransition@LoadScreen). match_finish_batch sees a red global with no failed row and restores the whole batch; it cannot drop the row. Guard the named row's body under NON_MATCHING by hand, take it off the symbol list, rerun (one foreground call per gate). Relink names one unit per run: B2 took 3 gates.
