# Time gate layers from outside the lock with checkpoint marks

Need: per-layer wall time of `gate._core` without editing the locked gate. C0100 wraps `_core` whole; this splits inside it.

Move: a scratch script under `.run/<phase>/` monkeypatches the callables `_core` reaches in order (`verifier_lock.check`, `_tool`, `matched_set.load`, `byte_compare.cut_check`, `build.build`, `_hashes`, `vv_inputs.input_path`, `matched_set.check`, `_objdiff`, `byte_compare.setup`, `relink.gate_check`, `provenance_lint.lint`, `verifier_lock.unlisted`) to stamp a checkpoint on entry. A layer's time is the gap to the next checkpoint, so in-between work (target hashes, report) is attributed.

Traps:
- Set `sys.pycache_prefix` before `import gate`, or the lock's pyc check sees your bytecode.
- Marks fire strict-next-only: nested calls (`check` calls `unlisted`, relink calls `input_path`) must not move a checkpoint.
- Scratch matched lists for row scaling must be whole units: a row-picked list makes relink refuse (`our objects and a cut object both define`).
- `config/matched_set.toml`'s comment header holds the literal `[[function]]`: count at line start, or you get one extra.
- `tools/__pycache__` already exists in the repo; its presence does not indicate a leak, a changed listing does.
- A one-commit public clone needs `git config core.hooksPath githooks` (check_env) and its upstream is origin/main, not origin/master.
- Layers here are bimodal run to run (relink ~17 or ~27 s, provenance ~5.4 or ~8.6 s) with nothing else in tasklist: take three runs, and read medians with their spread.

Source: 4.1 T1.c1, `.run/4.1/t1/gate_timed.py` (scratch).
