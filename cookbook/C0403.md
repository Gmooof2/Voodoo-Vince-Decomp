# Stamped stubs defeat a callee-bytes pin tag; discriminate by the pushed literal

Problem: boilerplate stubs (RegisterMe ctors: 60 B, push class-name `??_C@` literal + push creationFunc, call) are
masked-equal to one another. pin_rows' callee route (masked bytes + name rule on named outgoing dests) cannot tell them
apart while the literal and the pushed function are unnamed: a pin naming X's stub at Y's body passes.

Move:
- Add a route that keeps the callee route and adds a discriminator the masks hide: exactly one string literal pushed at
  the same mask offset on both sides, bytes equal through NUL, text == the class from the name (pin_rows `registerme`,
  tag `proto-pdb-public+literal+callee-bytes`, 5.4 T23).
- Prove the weakness before the fix: plant the row's retail literal VA with another row's literal bytes (an image copy,
  no pin-file edit); the old tag passes it (shown on all 4 real rows), the new route fails `literal-differs`.
- Control order: register the tag on the plain route first so the new control shows DID NOT FAIL, then add the check.

Applies to any family of compiler-stamped bodies whose only difference is an immediate (thunks, registration stubs,
factory ctors): find what the masks drop and check it explicitly.
