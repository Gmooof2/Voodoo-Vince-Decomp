# Ambiguous-row class writers and the ambiguous candidate lane

Context: 5.3 T3 (rules D128-D130). Writers `name_sites.py --ambiguous {bracket,fold-alias,fold-k1}`; lane in `candidates.py amb_lane`.

- Writer = measured class: the class predicates live in pool_buckets as module functions (`ruled_state`), so the writer uses exactly what Lane sizing counted. Lift them out of the `lane_sizing` closure and check that the lane counts in the regenerated doc do not change.
- Writer agrees with the gate: every line goes through `pin_line`, is replanted through pin_rows' own route for its tag, and refused lines are dropped and counted as disagreements. At T3: bracket 357/357, fold-alias 118/118, fold-k1 3 kept and 2 dropped (`route-fold:fold-single-public`).
- Lane pins by name: the ambiguous rows hold undecorated names and the pins are decorated, so the names are the PDB publics at protoVA plus the row names. Search every func line of both tables, because fold-alias VAs carry several lines (C0130) and the usual load keeps one name per VA.
- Capped rows (32 hits): the pin usually lies past the list, so `find_matches` confirms the masked bytes at the pinned VA (C0366). At T3, 158 of 171 admitted rows rested on this. The confirm was true at 10515 of 10515 in-list hits and false at 0 of 6285 other function VAs.
- Exclusion order: an unpinned row is checked at targetVAs[0], so most of the `fold` exclusions (2124) are unpinned short-inline copies, not refused pins.
- Plants: choose a plant that only the targeted check can refuse (an unnamed body whose callee bytes pass; a row whose pin is among its listed hits for shared-body). Otherwise a teeth run stays refused through another check. When `accepted()` already refuses site-corr, the teeth run for the site-corr control has to disable the whole not-accepted test.
