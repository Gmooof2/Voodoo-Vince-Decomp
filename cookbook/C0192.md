# Undecorated library names in symbols.txt: map the decorated public before comparing

Use: a check that compares a pin's decorated PDB public with the name symbols.txt holds at the same VA (two-names, fold tests).

- XDK/D3D/DSound library rows in symbols.txt carry undecorated names; the PDB public is decorated. Two forms cover every case today (10 rows, 4.2 T3/T5):
  - `_F@N` (stdcall C) reads as `F`: `_XInputClose@4` = `XInputClose`.
  - `?M@C@<ns>...` (C++ member) reads as `C_M`: `?Pause@CDirectSoundBuffer@DirectSound@@QAGJK@Z` = `CDirectSoundBuffer_Pause`.
- Equal after the mapping is one name, not two (D119). Anything else at the VA stays a two-names fail.
- Undo the mapping on a scratch run to prove it is the only thing clearing those rows (10 come back).

Ref: `tools/pin_rows.py`; `docs/ops/validation.md` "4.2 Pin-row check, sizing"; rules/D119.md.
