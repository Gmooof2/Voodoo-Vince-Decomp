# Accept a leaked value in history by blob id plus line carry (growing files)

Problem: a value (e.g. a LAN address) sits in accepted history blobs, and one of those files (a monthly
journal INDEX) is rewritten by every commit, carrying the old lines. A blob-id allowlist alone fails the
next commit: `--staged` scans the whole index, and each new version is a new blob.

Technique (audit_public.py address class, 2.1 T7):
- Tracked list = blob ids only (no value); pin it in the verifier lock and mark it `-text` in .gitattributes (C0052).
- Read the value from local config at run time; match as a whole token: `(?<![\d.])` + escape(v) + `(?!\.?\d)`.
- A blob holding the value passes iff its id is listed, or every line of it holding the value also occurs in
  a listed blob (lines gathered at run time from the listed blobs via `git cat-file --batch`). New lines with the
  value fail anywhere.
- Compute ids for worktree files too (`sha1(b"blob %d\0" % len + data)`); a CRLF checkout misses the id rule but
  passes the line rule (splitlines drops `\r`).
- Derive the list with a scratch script printing counts and ids only; split by first introducing commit
  (`git log --all --find-object=<oid>`, last line) against a boundary commit.
- Controls: listed pass; old-lines-only new version passes; one new value line fails; new file fails; near-miss
  (value + extra digit) passes; null value -> `not checked` on both streams.
