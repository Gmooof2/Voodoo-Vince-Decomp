# Cross-project overlap marker: carry it on the timing step, test it in a scratch folder

When: two projects on one machine must see each other's gate runs (shared-folder marker, e.g. docs/ops/gate_marker.md).
- Put writer and reader in the usage-record module (`timing.step(..., marker=cmd)`), not in the gate: marker write,
  remove and read errors join the step's single stderr warning, so the gate's stdout stays byte-identical (golden) and
  the locked gate change is one argument.
- Write after the run lock (a refused run is not running); remove first in the step's finally (covers SystemExit and
  KeyboardInterrupt); tmp + os.replace; readers glob `*.json` only.
- Gate the marker on the same flag that suppresses nested timing records (`_UNTIMED`), so control workers and nested
  `main()` calls write none.
- Reader: watcher thread looks at start, every N s and at end; liveness by OpenProcess + GetExitCodeProcess == 259
  (access denied = alive) plus an age cap; never delete stale files (they belong to the other project).
- Controls set the folder by env override under scratch, never the shared folder: a planted marker there reads as a
  live gate to the other project. Dead pid = a finished subprocess's pid; a mid-run marker needs a short poll env.
- Re-pinning a LISTED file changes the gate's unmasked `fp` line: expected, re-record the golden after showing the
  diff is that line alone.
