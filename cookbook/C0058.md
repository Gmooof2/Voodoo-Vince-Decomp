# C0058 — delinker trims intra-unit rel32 relocs (Trim superfluous PC-relative); trim off over-relocates
tags: delink,relocation,objdiff,coff,rel32,ghidra · date: 2026-10-26 · phase/task: 2.1/T3 · origin: T3.c1 trim-off trial

Supersedes C0035 (mechanism found; C0035's counts and Check stay valid).

Problem: a delinked target has a rel32 CALL/JMP/Jcc with no relocation whose target lies in the same exported
range (unit), another function; MSVC `/Gy` relocates it (REL32 against the callee). objdiff then scores equal bytes < 100%.
Mechanism: ghidra-delinker-extension COFF exporter option "Trim superfluous PC-relative relocations" (default true,
`CoffRelocatableObjectExporter.java:123-124, :200`; predicate `predicates/relocations/TrimSuperfluousRelativePC.java`,
source in `<ghidra_dir>/Ghidra/Extensions/ghidra-delinker-extension/lib/ghidra-delinker-extension-src.zip`) drops a
transparent RelativePC relocation when every primary reference from its instruction lands inside the selection range
containing it. delink.py exports one `/include-range` per unit, so every intra-unit branch is trimmed: intra-function
ones (correct for MSVC) and cross-function ones (wrong).
Not settable headless: the extension's `DelinkProgram.java:104` does `exporter.setOptions(getOptions(exporter))`, the
exporter's defaults; changing it needs our own export script (a copy with the Option value set false).
Trim off is no fix (2.1 T3.c1): the synthesizer emits RelativePC for every branch inside a Ghidra function, so with trim
off intra-function rel32 branches get REL32 against `LAB_` labels: crc32.obj K 0 -> 2 (`.text+0x21`, `+0xC9`); rel8
ones are dropped silently. Globals.obj gained its 1 cross-function site and nothing else, only because it has no
intra-function rel32 branch: test a trim change on a unit that has one.
Check: `PY tools/delink.py relocscan [--unit NAME]` census line `intra-section rel32: U unrelocated of N; relocated
inside own extent K` (N from XBE bytes over symbols.txt extents; K must be 0). 2.1 T3 cut: U 807 of N 807, K 0.
Fix (2.1 T3, route b, holds): keep trim on; `delink.py --fresh --rel32 NAME` (`_add_rel32`, after `_demote_labels`)
adds REL32 at exactly the census sites from the XBE bytes, against the object's own function symbol at the target
(field 0), else the `.text` section symbol (field = target offset); merged sorted into .text's table, later file
pointers shifted. Globals.obj: added 1 (+0x78 -> FUN_00125f98) = trim-off entry byte-for-byte; self-check 1893/1893;
gate 1/1 (BackupState objdiff 100%). Scratch, all 143 units: added 807 = N, section symbol 2x (unzip, Sprite),
coff_info --check-xbe 0 mismatch 0 unresolved. Covers code past a Ghidra bodyMax (sites come from symbols.txt
extents, not Ghidra bodies). Not covered: functions with no symbols.txt row (Ghidra FUN_ in gaps).
