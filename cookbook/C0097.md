# Pick batch input from pool_buckets.md, not from next_candidates.md alone

- `PY tools/pool_buckets.py` (after `candidates.py --write`) puts every unmatched pool row in one bucket; `docs/matching/pool_buckets.md` "Rows by bucket" lists ranks.
- Batch input: `ready` (unit opt set, claim directly), then `ready-opt-unknown` (one-flag opt control first, C0065). Both already exclude C0093 cut-extent rows and ledgered walls.
- `cut-extent` is the C0093 screen run pool-wide (`byte_compare.extent` on the cut vs row size): never draft these until the cut gains the missing symbol.
- The candidates `library` check fails two kinds of row: STL instantiations (`std::` name: `stl`, `stl-reloc`) and game functions with a std type in the signature (`@std@@`: `stdsig`, `stdsig-reloc`). `stdsig` rows are game code: matchable with opaque std decls (C0096, 2.5 T12 BeepFile); the filter is policy, not a wall.
- Single-target reloc gaps: the doc ranks unresolved targets that alone block a row; naming one target (symbols pin) unblocks that many rows.
- Ledger has no verdict field: walls known only from summaries live in the tool's `NOTES` table; add a row there when a task records a new one.
