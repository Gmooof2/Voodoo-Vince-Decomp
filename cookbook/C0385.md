# Diffing table loaders: call the real loaders, one table at a time

When: several tools parse the same hand-kept table (symbols.txt, symbols_pin.txt, functions.jsonl) with their own loader.

Move (5.4 T2.c2, log phase-ends/current/logs/T2.c2.md):
- A scratch script imports each tool and calls its real loader with the table path pointed at ONE table (monkeypatch the
  module's path constant); a loader buried in main() is copied verbatim and marked so.
- Normalize to (va, name, kind, size, status); diff per pair: rows kept/dropped, field differences; up to 10 example VAs
  per class, never bytes (D46).
- Then plant malformed lines on a copy (indented `#`, leading space, name with a space, 5-token row, lowercase hex, bad
  status) to see each loader's edge behaviour; real tables had none.

Findings worth knowing (5.4):
- candidates keys by VA (last line wins: symbols_pin overrides symbols.txt); gen_creationfunc takes the first sized func
  at a VA; va_dis/gen_creationfunc keep the first VA per name. 368 pin VAs carry several names; harmless today (kind never
  differs; status differs only symbols.txt unverified vs pin disasm-verified, the intended override).
- Malformed lines diverge (candidates/name_sites raise on an indented `#`; wave_rows drops a leading-space row) but
  pin_rows' grammar check flags all of them, so the gate stops them first.
- xdk_report's loader is `_jsonl` (:68), not :65.
