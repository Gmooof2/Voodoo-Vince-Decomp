# C0017 — Byte-compare obj function vs XBE: resolve relocs, mask unknowns, negative controls

# Byte-compare a delinked function against the XBE, with relocations resolved and negative controls

- Patch an obj copy: each reloc field in the function extent becomes the value the linker would write: DIR32 S+A,
  REL32 S+A-(P+4); P = function VA + (reloc offset - symbol value); A = the in-place s32; S from symbol tables by
  exact name, unique VA only. A section symbol's S = function VA - symbol value.
- Unknown S masks the field's 4 bytes; verdict `match` (equal, 0 masked), `provisional` (equal outside masks, >=1
  masked; never counted as matched), `mismatch`. Print resolved/masked counts, never bytes.
- Ghidra dynamic labels (DAT_/PTR_/s_/LAB_) are not in a non-dynamic export: use their `_<8 hex>` suffix only when the
  name is absent from the tables, and never for FUN_ names, or a removed-symbol control can never mask.
- Known-true on a delinked object is near-circular (the delinker derives relocs from the same bytes). The independent
  evidence is negative controls on scratch copies, each run as a real subprocess so the exit code is asserted:
  rewrite a REL32 reloc's symbol index (10-byte reloc record: offset u32, symbol index u32, type u16) to another
  table-resolved symbol with a different VA -> mismatch; same for DIR32 -> mismatch; drop one non-placeholder target
  (e.g. a mangled name) from a table copy -> provisional masked 1.
- Expected bytes from the XBE at compare time, sha1-checked against the pin; refuse (exit 2) any reloc type other
  than DIR32/REL32 inside the extent.
Source: phase 1.3 T7 (`tools/byte_compare.py --self-check`).
