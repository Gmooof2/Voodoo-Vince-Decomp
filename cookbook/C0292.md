# Control for a git stream reader's short read, and auditing gzip blobs

Problem: a `git cat-file --batch` reader that trusts `read(size)` and drops the exit status scans a prefix and says OK when git fails mid-stream. There is no real failing git to test it against.

Move (T16.1.c1, `tools/gate.py` `_c_audit_short_blob`):
- Patch `audit_public.subprocess.Popen` with a fake whose stdout gives a header `oid blob 100`, then 10 bytes, and whose `wait()` returns 1. Restore it in both the expect and the kw `undo`.
- Expect the reader to exit 2: `len(data) == size`, a delimiter of `b"\n"`, and returncode 0 after a full run.

Gzip blobs (G8): decompress before classify with `zlib.decompressobj(16 + zlib.MAX_WBITS)`, one member after another, with `max_length` bounded by a cap (64 MiB; the largest tracked ledger slice is 18.2 MB). Over the cap, a zlib error or a truncated member is a hit, never a skip. Check forbidden-hash on the raw sha1 too.
- Control: a scratch repo tracking `.claude-state/ledger/x.jsonl.gz` holding the gzip of the tool's own disasm fixture (`audit_public._fixtures()["asm.txt"]`), so the gate source holds no disasm run.
- Measure the real blobs by class and path (no content, D46) before landing: 24 slices, 0 hits.
