# Tell a call from a jump at a `rel` site: the opcode byte before the field

`proto_map.mask_proc` and candidates `sites` give `kind: rel` for call, jmp and jcc alike (`is_call_near` is tested, not stored). Stored rows cannot say which.

Move, at run time, on retail bytes only (nothing written, D46): `b = xbe[va + off - 1]`, where `off` is the field's offset in the function. A rel32 immediate directly follows its opcode, so `0xE8` call, `0xE9` jmp, `0x80..0x8F` with `0x0F` before it jcc; anything else is a refusal naming the VA, not a guess. Implemented in `tools/family_census.py`; checked against an independent iced decode on 3 rows (4.1 T9.c1).

Count (4.1, 2,919 rows, 25,425 sites): call 17,355, jmp 174, jcc 0, abs 7,896. jcc is 0 because every jcc targets its own extent and candidates skips those sites; a jcc count of 0 is expected there, not a bug. A tail `jmp` to another function is not in a call-shape, so `creationFunc` rows ending in a tail jump to the ctor have a shorter shape than those calling it.
