# XBDM file write on the box: delete then sendfile, replies seen live

When: writing a file to the box over XBDM 1.00.5849.1 (Cerbios), e.g. replacing a `default.xbe`.

- Box at the dashboard only: file verbs on F answer 402 while a title runs (C0082). Check `drivelist` has F first.
- `delete name="F:\...\default.xbe"` -> `200`.
- `sendfile name="F:\...\default.xbe" length=0x<hex>` -> `204` (send binary), then the raw bytes, then a final `200`.
  The `0x`-prefixed hex length is accepted (2.4 T5.1, T6 live).
- Delete first: overwrite behaviour is unproven live; the mock answers `410- file already exists` for sendfile onto an
  existing file (that 410 is a mock assumption, not a box fact).
- Prove the write: attributes before and after (`changelo/changehi` later), then `getfile` sha1 == source sha1. When
  the new bytes equal the old (e.g. a byte-identical relink or a restore), the change time is the only sign the write
  happened.
