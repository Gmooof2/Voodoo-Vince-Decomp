# Hole fill must run on created and split functions too

Extends C0071. Ghidra-delinker relocations come only from instructions inside a function body
(`CodeRelocationSynthesizer.process` is per Function). An instruction in a body hole keeps its raw VA in
the cut even when Ghidra holds the reference (`From X To Y READ`).

Cause seen (3.2 T10.c1, `?Update@TrolleyScreen@@UAEXXZ`): analysis decoded a misaligned `DEC ESP` at the
disp byte of `mov eax,[ebp+0x4c]`; flow stopped, the loop tail (0x5F B) was decoded but in no function.
ApplySymbols reached the function via `createFn`, and `fillHoles` ran only on the rename branch.

Fix: `tools/ghidra_scripts/ApplySymbols.java` calls `fillHoles(f, a, size)` after `createFn` and after
`splitAt` too. Summary `holes N instrs M` counts it; `hole <name> at <va> instrs <k>` lines name each.

Diagnose: `getFunctionContaining(site)` null + `f.getBody()` ranges vs the pin size; then the reference.
Symptom: `name_sites.py --check-cut` FAIL on a pinned site with no cut reloc (e.g. `__real@...` disp32).
