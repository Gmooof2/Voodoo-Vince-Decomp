# A file added to the verifier lock must also ship, or the public export refuses

Symptom: `export_public.py --commit HEAD` exits 2, `verifier_lock write rc 1 ... FileNotFoundError ... config/<file>`, with or without a parent. A commit from before the file was locked exports fine.

Mechanism: the export re-pins `config/verifier.sha256` by running the shipped `tools/verifier_lock.py write` inside `--out`. It hashes every `LISTED` path, so each one must be in the export: from `export/allowlist.txt`, or from `export/overlay/` (the two audit accept lists). 4.2 T5 locked `config/pin_accepted.txt` and listed `tools/pin_rows.py`, but not the txt. No cut ran between 4.2 and 4.4, so nobody noticed.

Move: in the task that adds a path to `verifier_lock.LISTED`, add it to `export/allowlist.txt` (or the overlay), after checking that it holds no game bytes (D46). Before a cut: run the export of HEAD into `.run/<phase>/` at prep time, not first at the close.

Evidence: 4.4 T15, commit a4732d9d added the line; the HEAD export then gave 610 files, `--public-ci` 0 hits.
