# C0111 — run.sh prints exit= first; a piped tail hides the exit code
tags: harness,run.sh,gate,exit-code,d26 · date: 2026-10-28 · phase/task: 3.2/T6 · origin: T6.c1 gate runs

# run.sh prints exit= before the tail: never pipe it into tail

`bash tools/run.sh <name> -- <cmd>` prints `exit=<rc>` as its first line, then the log tail.
A trailing `| tail -N` drops that first line, so the exit code (the only success signal, D26) is lost
and a red gate can read as green from its last lines.
- Read `exit=` from the first output line, or run the command unpiped through run.sh.
- The gate claim is exit 0 plus the bare `N passed, 0 failed of N`; both need the full run.sh output head.
Source: 3.2 T6.c1 (gate runs after the SwampRenderer edit).
