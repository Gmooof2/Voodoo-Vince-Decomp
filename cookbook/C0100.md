# Slow gate self-test: time each layer before scoping it

Problem: `gate.py --self-test` grew 6 s (1.5) -> 261 s (2.5) -> 401-406 s (2.6 clones), over the 285 s call bound.
The plan blamed the per-control whole-image relink; it was ~3 s. The real cost was the `audit_public` global
(`_tool("audit_public")`, default scope worktree + staged + history, ~25-27 s, growing with history) run once per control.

Technique:
1. Time each `_core` call without editing the verifier (it is lock-pinned): a scratch wrapper that imports `gate`,
   replaces `gate._core` with a timing shim, calls `gate.main(["--self-test"])`. Controls that refuse early (lock,
   cut-marker) take ~0 s; a constant ~25 s floor on every other control, even `empty-list` (no build), points at a
   global layer, not the build.
2. Time the suspect tool directly per scope (`audit_public.py`, `--worktree`, `--history`).
3. Scope an expensive global layer to the positive run plus its own control (`run_<layer>=False` in the other
   controls). Leave the key out of `glob`: a "skipped" non-pass verdict would make rc != 0 on its own and let every
   control "fail as expected" for the wrong reason.
4. A keyword named like a module (`relink=`) shadows that module inside the function: the layer raised
   AttributeError and the `relink` control still counted it as the expected failure. Make a control's expectation
   exclude a layer crash (`"relink error" not in g["relink"]`).

Result (2.6 T11): 378 s -> 43 s working copy, 41 s fresh clone, 20 of 20.
