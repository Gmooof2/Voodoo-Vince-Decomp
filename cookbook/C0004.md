# Detecting disassembly- and hex-dump-shaped runs in text without false positives

Use: firewall audit of repo text (plans, logs, transcripts) that legitimately carries hashes, offsets and addresses.

- Count consecutive lines of ONE shape; hit at N lines. Calibrate N on the full history: measure the longest legit run
  per shape, set N above it but at or below the smallest real leak worth catching. T8 values: legit max disasm 1, hex 2;
  N = 4 (disasm), 3 (hex): a 64-byte dump at 16 bytes/line is 4 lines.
- Disassembly shape: optional address + byte columns, a mnemonic from an EXPLICIT x86 list, then the operand
  immediately after it (register, `ptr`, `[`, `FUN_`/`sub_` label, 5+ hex target). Traps seen: an `f*` x87 catch-all
  and segment registers matched English ("For the ...") and Python (`for sp in ...`); an operand allowed anywhere on
  the line matched prose that names mnemonics.
- Hex shape: 8+ two-hex-digit tokens separated by spaces/commas (`0x` allowed) or 8+ `\x` escapes. 40/64-hex hashes,
  single offsets and address lists never match because they have no 2-digit tokens.
- Text blobs only (no NUL in first 8192 bytes); magics checked at offset 0 only, because docs and the tool source
  contain the literal magic strings.
