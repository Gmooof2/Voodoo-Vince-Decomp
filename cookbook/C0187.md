# C0187 — git status overstates change under autocrlf when a tool writes LF: use git diff --name-only
tags: git,autocrlf,crlf,windows,generated,candidates · date: 2026-11-01 · phase/task: 4.2/T1 · origin: T1.c1 Check 1

Use: deciding what a tool changed in a clone with `core.autocrlf true`, after a tool that writes tracked files with LF.

- `candidates.py --write` writes LF, so `git status --porcelain` shows `docs/matching/delink_residue.md` as ` M` while `git diff` is empty, on a pristine run too.
- Use `git diff --name-only`, or status plus an empty-diff check, to decide what really changed; a status listing overstates it.
- `docs/ops/setup.md` section 7 says the status is empty after this step; under `autocrlf true` it is not.

Ref: `docs/ops/validation.md` "4.2 Wrong names", Check 1; C0006.
