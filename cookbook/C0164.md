# Speed a per-line regex scan over git history without storing anything

Need: a history audit runs line regexes and value regexes over every blob, is too slow, and must not get looser. History repeats itself: here 212,111 distinct of 7,231,475 lines.

Moves, both within one process, so nothing can go stale:
- Memoise the line test results, keyed on the line, when the tests read only the line. Keep the line splitting and the run counting as they are. Here `max_runs` 48.3 s to 4.1 s.
- Before a value regex, test the literal it cannot match without (`ip in data`, `name.lower() in data.lower()`). The regex keeps its boundaries and lookaround. Here `address_hit` 40.4 s to 11.5 s; what remains is the regex on the blobs that hold a literal.

Prove it:
- Zero hits in the baseline proves nothing. Dump per blob: classes, run tuples, value booleans; compare digests over the whole history, on the real config and on a scratch config of made-up values that hit thousands of times.
- Plant each class in a scratch clone: a side ref from an old commit, a recent commit, the tip, staged, worktree, plus negatives that hold the literal with a boundary broken.
- `re.I` on a bytes pattern folds ASCII only, as `bytes.lower()` does: check all 65,536 byte pairs.

Traps:
- A scratch trial that puts `tools/` on `sys.path` makes process-pool children import the real module; they die with AttributeError. A dead pool must stay a failure.
- `.gitignore` may hold plant suffixes such as `.exe`: `git add -f`.
- A memoised default run looks faster on history than history alone: the memo is warm from worktree and staged. Compare like with like.
- `rev-list --objects` gives one path per blob, newest first. Any verdict that depends on the path sees only that path, and a blob-id skip list freezes it.
- Two runs of cl give different obj hashes: COFF TimeDateStamp, bytes 4-8. Mask them before comparing.
- Timing calls that pass the tool timeout move to the background; size batches to fit, or another timed call can overlap.
