# Folded ResourceHandle members: two walls for T9-admitted rows

When: a row calls a folded multi-public template member (`ResourceHandle<T>::~ResourceHandle`, `::operator=`;
alias pins C0130), or the row itself is a folded self-alias VA.

- Relink wall: if our object emits an out-of-line COMDAT copy of the folded member (visible inline body, `??_I`
  address-of `??1`), objdiff is 100 and bytes match, yet relink refuses
  `REFUSED our PE entry <x> + pe_base <y> != pin entry <va>`. Alias pins do not help. Seen 3.3 T14: ~VinceSwing
  0x00129BDA, SwampRenderer::SetEmptyTexture 0x000CA3E5. Lifted 3.4 T6.1 (relink: plain `.text` COMDAT code hole
  gets its /ORDER slot; other fold publics -> weak external; probes rc 0). Remaining: drop the NON_MATCHING guard
  (VinceSwing: restore the pin_emit scaffold + emitter row), `match_finish.sh`, full gate.
- Codegen trap behind it: cl 13.10 /O1 elides the dtor of a null temporary passed to `operator=(const&)` only
  when operator='s body is visible in the TU (without it: 80.95, the temp dtor is kept). So the body must be
  visible, which emits the COMDAT copy, which hits the relink wall.
- Pin-only wall: a self-alias VA name exists only in `symbols_pin.txt`; `match_finish.sh` precheck and
  `matched_set.py add` need a `symbols.txt` func line and refuse. match_one can pass (row ~ResourceHandle
  0x000292A6, draft under NON_MATCHING in Hannah.cpp). Needs a tool/plan decision.
- Also seen: `??_V` needs `operator delete[]` declared; a read retail does before an aliasing call -> pre-increment
  into a local.
