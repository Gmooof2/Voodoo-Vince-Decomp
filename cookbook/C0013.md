# C0013 — Ghidra analyzeHeadless on Windows: loader class name, no dot paths, pause hang
tags: ghidra,headless,windows,toolchain · date: 2026-10-25 · phase/task: 1.3/T4 · origin: T4 headless probe

# Ghidra 12.x analyzeHeadless on Windows: three traps

- `-loader` takes the Loader class simple name, not the extension name. ghidra-xbe's extension is
  `XboxExecutableLoader` (extension.properties) but its class is `xbeloader.XbeLoader` → `-loader XbeLoader`.
  Find it: `unzip -l <ext>/lib/<ext>.jar | grep -i loader`. A wrong name fails in option parsing:
  `InvalidInputException: Invalid loader name specified: <name>`.
- The project dir may contain no path element starting with `.` (`IllegalArgumentException: Path element starting
  with '.' is not permitted`), so never put a probe project under `.run/`; use the configured project dir.
- On any error `analyzeHeadless.bat` ends with `pause` ("Press any key to continue"), which hangs a non-interactive
  shell forever. Feed stdin from `nul` inside the .bat call (`... < nul`).
- Extensions unzipped into `<ghidra>/Ghidra/Extensions/` load headless with no GUI install step; their
  `ghidra_scripts/` dirs join the headless script path automatically (`-postScript DelinkProgram.java` resolves).
- Pin the JVM with `JAVA_HOME_OVERRIDE=<jdk home>` in `<ghidra>/support/launch.properties`.
