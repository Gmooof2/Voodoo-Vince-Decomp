# Gate-only failure from `#include <string>`: extra __ehhandler$ object and memcpy relink 0 VAs (2.5 T6.c2)

- Symptom: `match_one` passes, but `gate.py` fails `*objects* extra` (static EH funclet `__ehhandler$?_Copy@?$basic_string...` emitted into the unit) and `relink` (`_memcpy` resolves to 0 VAs). Seen on SwampLoader::Bundle copy ctor (0x000DADC8), which only calls the string copy ctor.
- Cause: the full `<string>` header makes cl instantiate the basic_string members inline into the unit; retail calls them externally.
- Fix: declare an opaque `std::basic_string` with only the members the body calls (the copy ctor), as `src/Apps/Vince/scripts/Sewers/JaniceCutscenes.cpp` does. The call then stays an external rel32, as in retail.
- Check: always run the full gate before claiming a match in a unit that pulls STL headers; match_one alone does not catch this.
