# Retail global reload after a call (g_swamp): only a volatile access cast reproduces it, and D116 bars it

- Retail re-reads `g_swamp` where cl reuses the loaded value (CSE) in every allowed form (C0345 LightBeam, C0348 RenderGameScene, C0352 LightningFlash, GenerateEnvironmentMap). `SwampRenderer& v1 = (*(Swamp* volatile*)&g_swamp)->GetRenderer();` (volatile on the first read only) matched SwampTextureEffects::GenerateEnvironmentMap 0x000D69DF (objdiff 100, bytes match) but is a D116 form (volatile/global address trick): not kept; a ruling question. Declaring the global volatile for the whole unit breaks other matched rows, so retail's global was not volatile.
- Pointer stand-ins competing with a cached 0 constant for ebx lose (UpdatePic 0x0013DD41: register priority contest).
- A guard-flip script must stop before match_one when its replacement misses (LF vs CRLF files), or a guarded 0.0 run is logged as an attempt.
