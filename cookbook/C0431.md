# C0431 — Redaction table: separator-less forms match whole identifiers only, leak check shares the patterns
tags: d46,redact,audit,clone,leakcheck · date: 2026-11-10 · phase/task: 5.5/T9 · origin: T9 inclone.py

Problem: a redaction table built from config values holds bare relative values and stems (a 6-letter word like a
tool's name). Matched as plain substrings, they rewrite key names (`<label>_project_dir`) and hit inside the
labels themselves (`<word_project_dir>`), so a leak check over redacted logs reports false hits and the output is
garbled. Seen 5.5 T9: `ghidra_project_dir` is relative, one word.

Move: compile the table once (`public_walk.RX`): a form holding `/` or `\` matches anywhere; a form without a
separator only as a whole identifier (`(?<![A-Za-z0-9_])v(?![A-Za-z0-9_])`), case-insensitive, longest first. The
leak check counts with the same compiled patterns, never a second matcher. Add the user home folder as one more
form (`home`): interpreter and venv output prints it. Prove both with a plant: raw output leaks every key, wrapped
output leaks 0 (`PY tools/inclone.py --control`).

Evidence: 5.5 T9, logs `.run/5.5/logs/t9_*.log`, leakcheck 8 files 0 hits; before the fix 2 files hit on
`ghidra_project_dir`.
