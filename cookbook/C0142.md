# Name a near-identical retail row: anchor window + similarity + accepted-caller xref (near-corr)

Use: a proto_map near-identical row (no masked-byte hit) needs its prototype name without any byte identity.

Method (`tools/name_sites.py` `near_ctx`/`near_check`, 3.4 T2):
1. Name = the single PDB public at protoVA (else no-public / multi-public).
2. Window: rebuild proto_map LIS anchors from functions.jsonl identical rows (protoVA, targetVAs[0], length),
   drop the row's own pair, `gap_ranges(anchors, bisect_left(protos, pva), exec sec bounds)`; rva must lie inside.
3. Similarity: `proto_map.tokens` both sides (retail bytes capped at 15 * len(ptok)), slice ctok to len(ptok),
   `proto_map.similarity >= THRESHOLD`; for the row's own candidateVA it reproduces proto_map's stored value (drift 0).
4. Caller xref (C0059) indexed once: accepted-status table funcs only (symbols.txt unverified/verified, pins
   disasm-verified; never site-corr/boundary/near-corr), counterpart = unique proto public of the name,
   `Images.match` must hold, then each rel mask with proto dest outside the caller gives (pd, rd). Pass needs
   >= 1 site pd == pva and rd == rva and no conflicting site (pd == pva, rd != rva or rd == rva, pd != pva).

Numbers (3.4 T2.c1): 1260 near rows -> 240 pass (96 new pins, 144 already named); no-xref 1009; admitted skew large
(>=129 bytes 156, <=16 bytes 2). Same check over the 1944 identical candidates rows: 975 pass, 922 no-xref, 36
multi-public, 8 outside-window, 2 similarity-below, 1 xref-conflict, 0 wrong names.

Traps:
- Caller xref cannot name vtable-only or unreferenced functions: ~half the rows have no accepted direct caller,
  so "every identical row passes" is not reachable for any unit with near rows; plan controls around abstention.
- Similarity alone admits decoys: the planted decoy (proto 0x0040BA75 -> 0x000215BD, sim 70.59) fails only on window;
  the swapped pair (sim 81.82, inside the window) fails only on xref.
- A masked-identical caller can hide a callee change (??1PropellerMain +0xE: proto ~CritterMain, retail
  ~SwampSceneNode); the positive control excludes it as `callee-moved` when proto_map maps the proto target elsewhere.
