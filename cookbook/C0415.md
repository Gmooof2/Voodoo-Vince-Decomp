# Re-cut-freed rows need one passing match_one row before the batch finish

- Trap: `match_one --table` refuses (`FAIL N of M matched symbols unledgered`) when a matched symbol has no passing attempt/listing row (rc 0). A row freed only by a pin re-cut whose last ledger rows are pre-cut failures (rc 1), finished by `match_finish_batch` alone, leaves exactly that (5.4 T26: 8 creationFunc rows; found at T16's close).
- Move: after the re-cut, run `PY tools/match_one.py --task T<n> --workdir <name> --symbol S` once per freed row (PASS objdiff 100 + bytes), then `match_finish_batch`. The resubmission check does not refuse when the source changed since the failing run (an un-guard counts); otherwise add a comment line (C0413).
- Repair at close: the same run under the close task id, then `--table`.
