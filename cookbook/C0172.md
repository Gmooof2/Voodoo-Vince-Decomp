# A private value repeated in an agent's reasoning blocks the next commit

Symptom: a commit fails in the pre-commit audit, `HIT staged boot-folder` or `original-install`, on a
`.claude-state/journal/<date>/*-thinking.md` note. A plan edit reports `applied: ... (not committed: ...)`.

Cause: journal notes record reasoning text. An agent read a value from an accepted file and repeated it while thinking.
Reading it is fine; the repeated line is new, so the audit's line rule does not cover it.

Fix, while the note is uncommitted:
- A scratch script reads the value from the local config and replaces it with its label, whole word and any case, in
  that dated folder only. It prints paths and counts, never the value.
- Re-stage the notes, then run `audit_public.py --staged` and `--worktree`.
- Run the script again at the end of the turn: the reasoning that spelled the value may be written after the first run.

Do not add the notes to the accept list: that puts the value into history, for no gain, and changes a locked file.

Prevention: in reasoning too, name a private value by its label.
