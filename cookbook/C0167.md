# C0167 — Trial removals by rounds: one construct per file per gate; a green row is signal only if a matched body depends on it
tags: fake,trial,gate,rounds,non_matching,readability,driver · date: 2026-10-30 · phase/task: 3.6/T8 · origin: -

Use: try removing many source constructs when one gate costs ~2 min and prints a row per function.

- Rounds: units build separately and a unit's failure stays in its rows, so one gate tests one construct per file; round k tries the k-th construct of every file. 192 constructs took 15 rounds, not 192 gates.
- Driver: a frozen table of byte-exact edits (id, path, old, new), dry-run cumulatively before the first gate. Require all N rows parsed each round; a run with fewer rows is invalid, never a pass. Revert the failures, then one proof gate on the kept set before its commit; only the proof gate's global layers count, because `relink` fails in any trial round holding a failed row.
- A green row is signal only if a matched function's code depends on the construct. Check where the construct's effect lands, not where the edit sits: a struct member or inline helper outside `#ifdef NON_MATCHING` can matter only to a function inside it (3.6 T8: Vector4 ctor, Matrix::Apply, both for Sprite::Render). Read the label's named function against the guard lines; a parse of the changed lines misses these.
- Such a green is not kept: restore it verbatim and route it to the label review.
- Proof at the end: base + kept edits, applied to the code part of every line, equals HEAD.

Traps: Python on Windows finds system32 `bash` first, name Git Bash. `readability_census.py` refuses a dirty `src`, and `--label` keeps only text inside `<!-- readability:X -->` markers.
