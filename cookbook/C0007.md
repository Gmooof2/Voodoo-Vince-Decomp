# Rich header: decode and what /GL does to it

Layout (R1.2-005: ntcore Pistelli, object crate rich.rs, LIEF): find `Rich` (0x68636952) in the DOS stub, key = next
dword; walk back XOR-decoding dwords until `DanS` (0x536E6144); then 3 padding dwords (0 after XOR), then
(comp.id, count) pairs; comp.id = (prodid << 16) | build. Stored key = recomputed checksum (proven on T5 fixtures).

Proven on cl 19.51.36260 fixtures (phase 1.2 T5, `PY tools/pe_info.py --self-test`):
- plain `/Zi /O2`: one entry per language, Utc1400_C 0x0104 and Utc1400_CPP 0x0105, build = banner build.
- `/GL` + `/LTCG`: C and C++ objects BOTH counted under Utc1400_LTCG_C 0x0108 (count 2); 0x0109 never appears.
  A check for "C++ present" must accept LTCG_C under /GL.
- The comp.id holds only the 16-bit build, never the 19.xx minor; builds do not map 1:1 to minors
  (python.exe "MSC v.1951" carries build 35721, our cl 19.51 is 36260). Static CRT libs add entries at older builds.
- For VC 7.x retail exes, expect the same pattern only as a hypothesis: whether 7.1 /GL also collapses to one LTCG
  prodid is unverified.
