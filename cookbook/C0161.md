# A history scan on a CI host must refuse a shallow clone

Use: any tool whose claim is "over the full history" and that may run on a host you do not control.

- CI checkouts are shallow by default (GitHub `actions/checkout` fetches one commit). `rev-list --objects --all` then
  succeeds and reports `0 hits` over one commit, so the tool exits green having read almost nothing.
- Guard in the tool, not in the workflow file: `git rev-parse --is-shallow-repository` != `false` -> refuse (exit 2).
  The workflow sets `fetch-depth: 0`; if someone drops it, the run fails loudly instead of passing quietly.
- Self-test: `git clone --depth 1 file:///<posix path> <dest>` in the scratch folder, run the real CLI there, assert
  rc 2 and the word `shallow` (a plain path clone ignores `--depth`; `file:///` honours it; spaces in the path work
  unencoded on Git for Windows).
- A public-host mode also ignores test env overrides, so it reads nothing outside the repo.

Seen: tools/audit_public.py `--public-ci`, 3.6 T3.
