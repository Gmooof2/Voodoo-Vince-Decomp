# Nested-class operator rows: no FUNCTION tag passes the gate today

- Rows `X<...>::nested::operator*()` (deque `const_iterator::operator*`, vector<bool> `reference::operator=`)
  match_one 100 + bytes equal, but the gate refuses both annotation forms:
  - FUNCTION + `NAME: proto-pdb` -> `FAIL provenance ... const_iterator::operator* not in default.pdb names`:
    `provenance_lint.py:110` CALL_NAME keeps only `ID::operator`, dropping the outer `std::deque<...>`.
    The PDB index has `std::deque::const_iterator::operator*` (probe `pdb.resolves`: True).
  - FUNCTION without NAME -> `FAIL globals: annotations` (every FUNCTION needs its NAME line).
- `X<...>::operator*` (one level, e.g. reverse_iterator) passes only by the bare `operator*` fallback.
- So keep such rows under `#ifdef NON_MATCHING` with the C0212 note; never unguard them in a batch
  (5.2 T12 batch 2 went red on 4 of them). Lift = a provenance_lint CALL_NAME fix (gate tool, verifier-locked:
  a plan task with a control).
