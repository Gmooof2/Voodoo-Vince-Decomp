# Batch cut: name_sites --unit --apply needs a fresh pool; callee/fold pins can add relocs to old objects

From 4.4 T7.1.c1 (batch B1, 5 units, 234 pins).
- `name_sites --unit U --apply` right after a cut REFUSES "0 pool units match": the pool is candidates.jsonl from
  before the cut. Run `candidates.py --write` first, then apply per unit.
- Old-object compare (pre-cut copy vs new, via coff_info.parse: section bytes, (offset,type) relocs, defined symbols)
  is needed: a new `func` pin can turn an inline call/jmp displacement in an ALREADY-delinked object into a REL32
  (+1 reloc, 4 bytes become addend) and rename the defined symbol there. Seen: `?insert@_Tree...` 0x000380F3 (Whammy
  pins) in BeepFileSystem.obj; fold thunk `?Union@AABox` 0x000DDEF3 (SwampFireFlyNode pins, callee-bytes) in
  SwampGeometry.obj. Not name-only (D121): disable the pin and re-cut, or route to review.
- check-cut `neither pinned nor residue`: name_sites drops from residue every target it NAMES, also when the pin is
  not written (replant dropped a site-only pin, e.g. ?SetHealth@Critter 0x00018110 at min-rows 3) or is DISABLED
  (Puddle _Tidy 0x0012B64E). Accounting, not a cut regression: the cut relocation is unchanged. A regression is a
  FAIL where the cut reloc does not name the pin.
- Re-cut ~556-570 s per cut for 5 units (B1).
