# Testing a LISTED tool change in an existing public clone

- A public clone's `config/verifier.sha256` differs from the private one: the cut ships its own accept lists
  (`config/audit_*_accepted.txt`, overlay), so their hash lines differ.
- Copying the private lock into the clone fails `verifier_lock check` on those lines and every gate-backed control
  goes red (5.5 T32: 114 of 231).
- Move: save the clone's originals under `.run/<phase>/`, copy in the changed tool, and in the clone's own lock
  replace only that tool's hash line. Run, then copy the originals back and compare `git status --porcelain` before
  and after (git checkout/restore are denied).
- A real cut re-pins the lock by the export tool, so this is only for a pre-cut check.
- Pair with C0447: a control that needs a file the public tree lacks gets a stated skip (`config/PUBLIC_TREE` present
  and the file absent), is dropped from the public count, and fails privately when that file is missing.
