# Scratch repo under the project root: repoint the harness tools, or they act on the real repo

Use: a control that runs a harness tool (`commit_task.sh`, `plan_edit.py`) in a scratch repo under `.run/`, or a hook that calls one.

- `tools/commit_task.sh` walks up from `$PWD` to the nearest `.claude/pa.json`, then `cd`s there. In `.run/<phase>/x/repo` that is the real repo: it committed there (ddad41a3, "router: x"; the journal files it auto-stages for loop ids). Put a `.claude/pa.json` holding `{}` in the scratch repo before the first call, and assert the real HEAD did not move after each.
- `tools/plan_edit.py` obeys `PA_PROJECT_ROOT`, which the mod sets, ahead of its own location. A scratch copy therefore answers from the real plan: deleting the scratch plan changed nothing and the control still passed. A hook sets `PA_PROJECT_ROOT="$ROOT"` on the call; a control leaves it pointed at the real repo so it proves the pin.
- `plan_edit.py` imports `_genplan`: copy both.
- Tell: a "failed lookup" control that passes, or a commit whose author is the scratch identity in the real log.
- Plan task lines start `- T<n> |`, and `review: yes` also occurs inside `done-when` text: read `review` from `show --task T --json`, never from the line. No `review` field means false.
- A refused case followed by `git reset --hard HEAD` also restores a plan flip when the plan is tracked in the scratch repo: flip again before the next case.
- A shell control starts `cd "$SCRATCH" || exit 1`, in a subshell, before any edit: a failed `cd` ran the plant in the real repo (real `tools/gate.py` appended and staged; caught by the hook).
- `bash` from Python on Windows is WSL's: use Git's `usr/bin/bash.exe`.

Ref: `githooks/commit-msg`; `docs/ops/validation.md` "4.1 Lock-list commit hook".
