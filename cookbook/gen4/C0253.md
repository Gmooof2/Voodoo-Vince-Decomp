# Speed up a verifier-locked linear scan without changing its output (4.4 T3.c1, relink _link)

- Relink `_link` spent ~250 of 270 s in per-hole linear scans (`hole_at`, `_split` owner lookup, `ours_before` membership). Replaced with: bisect over sorted post-dedupe hole starts (valid because the overlap refusal guarantees hi_i <= lo_j), a per-symbol cache for the owner lookup, a set mirroring every `objs` append, and a per-section cursor over ascending holes. 270 s -> 16 s; LINK itself 2 s.
- Prove "same output": hash every file in the link dir before/after (two runs each). Only `gate.exe`/`gate.map` differ run-to-run (PE TimeDateStamp at 0xC8-0xC9, map `Timestamp is` line); normalize those and the rest must be byte-identical. Diff the self-test `control ` lines before/after: must be empty.
- Order: edit the locked file -> `verifier_lock.py write` -> self-test/gate. Running the self-test first fails 44/107 on `lock: sha256 mismatch` (not a regression).
- Keep refusal texts and their order exactly; controls key on them.
