# Classifying retail XBE code as game / XDK / unidentified

- Module rule (default.pdb): xdk = objname under `D:\xboxfre-jun03\` OR lib basename in the XBE library table OR lib under `Microsoft Xbox SDK\Xbox\Lib\`. The third criterion is needed: OLDNAMES.lib (2 modules) is in neither the table nor the build tree; xgraphics.lib misses the table name `XGRAPHC`. Gives 306 game / 382 xdk / 1 linker.
- Join proto_map rows to modules by protoVA -> PDB proc, never by module name (module names repeat across libs).
- Byte denominator: T5 Ghidra function bodies inside EXECUTABLE sections, not raw section sizes. This XBE flags `.rdata` (0x6) and `.data` (0x7) executable, so raw sizes would swamp the bucket with data.
- XBE section names abbreviate library names: D3D/D3DX are prefixes of D3D8/D3DX8; XGRPH = XGRAPHC only as an in-order abbreviation; XPP has no table library but is xdk by attribution.
- XbSymbolDatabase agreement with PDB xdk procs is low at XDK 5558 (229 of 1447 VAs); report it, never use it as the xdk population.
- Tool: `PY tools/xdk_report.py`; evidence `docs/evidence/xdk.md`.
