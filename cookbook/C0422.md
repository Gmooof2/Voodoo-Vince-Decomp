# symbols_pin.txt has mixed line endings: edit it bytewise; D136 in-unit anchors can leave a module with none

- config/retail/symbols_pin.txt mixes LF and CRLF (386 of 7111 lines CRLF at 5.5 T4). `Path.read_text` /
  `write_text` normalises and rewrites hundreds of lines. Comment a line out on bytes (`read_bytes`, split on b"\n",
  keep each line's own ending), then check `git diff --stat` shows only the intended lines. Raw `git checkout --` is
  denied here: rebuild from `git show HEAD:<path>` bytes.
- D136 (pin_rows `State.anchors` keeps only matched procs whose retail VA is inside the module's units.toml text
  range): a module whose only matched procs are COMDATs placed in other units has no anchor left, and its bracket rows
  fail `route-bracket:no-anchor` (5.5 T4.c2: 0x000B410E, SwampScene.obj, disabled). Re-run every bracket row after an
  anchors change; the row comes back when an in-unit function of the module is matched.
- Writer vs gate on fold dests: name_sites `callee` needs exactly one proto public at a dest, pin_rows `callee` accepts
  any one of several (D119). `--recheck bracket` therefore refuses rows the gate passes (27 at 5.5 T4); not a gate hole.
- callee-down (unnamed rel dest must be masked-equal one level down) is a twin discriminator for the bracket route
  only: on the func and fold routes it refuses 34 passing rows whose callee changed between prototype and retail.
