# Build objects live per source path: find them by `build.obj_rels()` or `b["obj"]`, never by basename

- Since 5.1 T4.c2 (2e3340463) `build.py` writes `<out>/<rel source path minus ext>.obj` (dirs created), so two units whose retail objects share a basename (scripts/french_quarter Switch.obj, unit 331; core Switch.obj, unit 480) build side by side; the C0247 finish refusal `obj name X also built from Y` is gone. A same-output-path pair (e.g. `x/Dup.c` + `x/Dup.cpp` under one objname) is still refused: `obj path X also built from Y`.
- Consumers: `build.obj_rels(units_path)` maps lowercased unit name -> obj path relative to the build dir (relink `_ours`, pin_rows `i10`, matched_set `built_from`, gate controls); `_all_ours` counts with `rglob("*.obj")`. Code holding a build record uses `b["obj"]`.
- Control `build-objname-path` is a `direct` control (CFG_CONTROLS); run it alone with `PY tests/control_only.py build-objname-path` (5.1 T11; was the scratch `.run/5.1/t4/one_control_direct.py`).
- Trap: piping `run.sh` into `tail` hides the exit code; run the gate alone and read `exit=`.
