# opt-unknown units in a batch: one unit at a time; implicit __that members; global member-pointer local
- An unit file under src/ whose `config/retail/units.toml` opt is still "unknown" makes every build refuse, so every gate (match_finish) in the batch fails rc 2. Set the unit's opt from its control (C0137) before writing the next unit's file; work one unit at a time. Seen 3.4 T8.c1: PipeGas finish failed because SwampLightning.cpp was already on disk; the next finish committed without PipeGas.cpp (repair commit 03370332).
- Batch opt result (3.4 T8.c1, ten units): `/O1 /Oy` passed every control; `/O2` failed except on a pure leaf (GameRegions: only `/Od` discriminates, O1 vs O2 left open in its `# was` comment).
- Compiler-generated copy ctor / operator= (PDB param `__that`; operator= absent from `pdb_types names`) used by a matched row: keep them implicit. An explicit definition fails the proto-pdb provenance check even under NON_MATCHING. Pin their bodies through `// !FAKE:` emitter functions plus `[[emitter]]` rows (C0122; SaveLoadVar precedent; WaterRegion Splasher). Contrast C0117: explicit is right only when the PDB names the member.
- /O1: retail keeps a global's member pointer in a register across a float store through `this`, ours reloads it: the source had a local copy (`SwampRenderer* renderer = g_swamp->_renderer;`, ShootingCam::AimCenter 88.24 -> 100; C0119 family).
- Two PDB class records for one class: use the later one when retail's offsets match it (MirrorUrnMain `_wasMoved` 0xE1; LevelScript 0x4C-0x50); say so in the file header.
- A row calling a folded member's non-representative name relinks cleanly when the fold-alias pin pair exists (C0130).
