# MSVC typedef names are S_UDT records, not TPI names

A set of type names built from TPI (LF_CLASS/LF_STRUCTURE/LF_UNION/LF_ENUM names, `pdb_types.py names`)
misses C typedefs: `typedef struct inflate_huft_s inflate_huft`, `Bytef`, XDK `LAUNCH_DATA`. CodeView
records a typedef as S_UDT (0x1108: type index + name) in the global symbol stream and in module streams,
not as a TPI leaf.
- A name lint or cast census that must see typedef names reads S_UDT from the globals/module symbols too,
  resolving each S_UDT type index through TPI to its struct.
- A missing typedef name is not evidence the name is invented: check S_UDT before calling it unresolved.
Source: 3.2 T6.c1 (provenance_lint `--casts` gap).
