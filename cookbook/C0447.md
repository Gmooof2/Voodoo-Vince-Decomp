# Hook controls built from the running tree fail in a public clone

Recurrence of C0173 and C0382, in the 5.5 T14 hook controls (gate_controls `_hook_tree`, :1139).
- `_hook_tree` copies the running tree's `config/local_paths.json` into its scratch "private tree". A public clone's
  config is the no-box one (original_install, boot_folder, xbox_ip null), so the T14 hooks' "a value class not
  checked in a private tree blocks" rule fires on the clean legs too: rc 1 everywhere, control "DID NOT FAIL".
- The controls also run `githooks/commit-msg`, which never ships (export/allowlist.txt:13): rc 127 in a clone.
- Private self-test is green, so nothing shows it until a public walk (5.5 T18: 227 of 232).
Fix pattern: a control's scratch fixture writes its own complete, fake config values instead of copying the
running config; a control that needs a file the public tree lacks checks for it (or `config/PUBLIC_TREE`) and runs
the legs that exist. Before a phase's public walk, run the self-test once in the last public clone after any
change to controls.
