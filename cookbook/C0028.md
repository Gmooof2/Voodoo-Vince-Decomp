# cl 13.10 /O1 block layout follows source order: match retail branch order by source shape

Context: matching MSVC 7.1 (cl 13.10.3077) functions at /O1 /Oy (Voodoo Vince retail, 1.4 T9.c1, LocString_GetStringID).

- At /O1 the compiler lays basic blocks out roughly in source order; flags do not reorder them.
- Read the retail block order first (which block falls through, which is the jcc target), then shape the source.
- Example: two early returns `if(!p) return -1; if(id>n) return -1; return v;` put the -1 block first with a `jbe`
  over it (16 B diff). Retail had the value as the fall-through: `if (p != 0 && id <= n) return v; return -1;`.
- Lever order (D54): block order / source shape before flag ladder when the diff starts mid-body at a branch.
- Related: /GS pins nothing in a function without a local array (no cookie); cl 13.10 has no `/GS-` (D4002, exit 0; C0026).
