# Over-256 B forms (5.2 T11): x87 temp binding, stored bools, failure tails, slot packing, rsqrtss tell

Source: 5.2 T11 coders c1-c4 (logs phase-ends/current/logs/T11.c<k>.md). cl 13.10.3077, /O1 /Oy.

- `v += Vector4(w)` hand form: bind the temp by reference (`const Vector4& t = Vector4(w);`, `!FAKE`) -> retail `fld st(1); fadd [mem]`; a named value temp gives `fld [mem]; fadd st(2)` (LightManager::AddLight/GetAllLights 95.25 -> 100).
- `bool b = f != 0.0f; if (!b && (type == 1 || type == 2))`: read `type` into a local before the test and cl keeps the stored bool (`mov [b],1; jp; mov [b],0`); otherwise it folds b into the branch (58.57 -> 100).
- cl merges two ternaries on the same condition into one branch (paired pointer assignment).
- An inline float accessor read after a call is spilled to a stack temp before the call; a direct field read is not.
- String literal to a `const SwampString&` param: implicit conversion builds the temp before all other args; explicit `SwampString("x")` builds it in arg order (86.2 -> 100; see also C0218, C0226).
- Local zeroing stores follow source position: move `Vertex v; v.color = f(); float a = 0;` before the vector declarations (97.75 -> 100).
- One failure tail: `goto fail` from inside a loop reproduces retail's single shared failure block, including the jump past a null check (Swamp_LoadWorld 72.9 -> 81.9).
- Slot packing: sibling `{}` block scopes give two named locals one slot; a `push_back` temp in the enclosing scope is still not packed with them (ZoneNode::Init 99.54, frame 0x28 vs 0x24, guarded). Same wall family as C0323.
- Nested by-value inline Vector3 `operator+`/`operator*` with float-variable args stay out of line at /O1 and /Ob2; staged stand-ins in `{}` blocks plus `const Vector3&` refs approach retail's inlined-temp frame sharing (WhammyProjectileMain::FrameTick 66 -> 92.11, guarded; operators have no PDB record -> D78).
- D116 tell: inline `movss/rsqrtss/movss` with no `and esp,-16` in the frame is inline asm; `_mm_rsqrt_ss` adds the alignment. Guard as the D116 wall at once (SwampShadow::RenderNow 83.58).
- `sete al; test al,al; mov [m],al` (retail) vs our `sete [m]; cmp [m],0`: unsolved in 13 tries (ZoneNode::RenderChunks 95.70).
- Tooling: `llvm-objdump --disassemble-symbols` stops at the first `LAB_` label in a delinked cut object; use `--start-address/--stop-address` (section offset = VA - text_start). A `while read` loop over match_one needs `</dev/null` (match_one eats stdin) and `\r` stripped from Windows-written lists.
