# git rev-list --objects names each blob once

`git rev-list --objects <revs>` prints every object once, with the first path it was reached by. A blob committed at
two paths (identical content) appears under only one of them.

Consequences:
- A path-based rule over history (an exemption, a per-directory class) sees one path per blob; identical content
  elsewhere inherits whichever path came first.
- Self-test fixtures that plant the same bytes at two paths and expect per-path results pass in worktree/staged
  scopes and fail in history. Give each fixture distinct bytes (e.g. append a marker).

Seen: tools/audit_public.py self-test, 1.7 T7 (journal oversize exemption): `big.dat` and
`.claude-state/journal/big.md` shared a blob; history reported only one.
