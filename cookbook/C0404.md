# Chained naming writers: pass 2 reads pass 1's pins from the pin file, never in-memory pairs

When: a class whose callers are named by another class (abs-site after registerme, 5.4 T11.1.c1).

- The writer for the second class reads its accepted callers from the pin table at run time; run class 1 `--apply`,
  then class 2. Dry-run class 2 against a scratch pin copy with class 1's lines appended (`--pins <copy under .run/>`; the env NAME_SITES_SYMS_PIN is refused since 5.5 T5).
- A control whose plant needs pass-1 callers (push-start-planted) finds no plant on the real pin before pass 1: run
  it on the scratch copy, or after the apply.
- Stamped stubs (RegisterMe, 60 B) refused on callee bytes when the pushed creationFunc dest already carries another
  name: `boundary_*` placeholders (46) and retail-folded creationFuncs of another class (13). Not a writer bug.
- A push site counts only after checking the opcode (`push imm32`, 0x68) before the operand; an abs immediate inside
  a mov is no push (D135).
- D135 non-entry dests: size = proto proc length, listed with their push site for gap_functions `at` (call-site).
