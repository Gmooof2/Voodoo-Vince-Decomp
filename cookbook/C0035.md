# VC 7.1 TPI LF_ARRAY: element count = byte size / element size; forward refs can be ambiguous

- LF_ARRAY 0x1503 body: elemtype u32 @0, idxtype u32 @4, byte size numeric @8, name. No count field: count = size / sizeof(elem).
- Element size: primitives by CV encoding (mode 4 = near32 ptr 4; kinds 1/2/3 = 1<<sub; 0x70-0x77, 0x68/69, 0x40-0x42 table); LF_POINTER 4 (ptr-to-member refused); LF_MODIFIER/LF_ENUM recurse to the underlying type; class/struct/union size numeric @16 (union @8).
- Trap: a forward-ref element (prop 0x80) has no unique name in default.pdb, and one name can have full records of different sizes in different modules (254 names; SpotlightGlowVertex 0x1c at ti 0xca2f and 0x14 at 0xfdeb, array 0xfde6 of 0x50 bytes uses the forward ref 0xca2b). First-match-by-name gives a wrong or non-integral count. Take every candidate size; accept only when the dividing candidates give one count, else refuse.
- `tools/pdb_types.py` does this since 3.1 T3 (`tname`, `tsize`); all 882 arrays in default.pdb render.
