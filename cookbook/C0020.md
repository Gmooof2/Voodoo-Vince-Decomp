# Unit (obj) extents in an MSVC 7.1 /Gy image: SC runs, main run, grouped tail sub-sections

Proven: 1.3/T10 on prototype default.pdb (DBI section contributions, C0018) + proto_map rows; `tools/units_seed.py`.

- Collapse exec contributions per section (sorted by offset) into runs of consecutive same-module records. In proto `.text` 9475 records -> 792 runs for 502 modules: each game module has ONE main run in link order, plus pieces in a tail block after every main run (here from .text+0x13bd4e to the end).
- The tail is the linker's grouped `$`-suffixed sub-sections, in module order, one block per sub-section: (1) proc-less 10-B multiples (EH handler thunks, no S_*PROC32), (2) `$E<n>` procs (10-13 B; dynamic init/atexit stubs), (3) local-static atexit stubs named `` `X::Instance'::`2'::v ``. 198 of 306 game modules have procs there (893 procs); a naive "procs outside the main run" test flags them all as split.
- So a unit's code is the main run (one range) + tail pieces; a single [start,end) per unit covers the main run only. Treat tail procs as their own count, never as interleaving; true interleaving = own procs in another module's main-run region.
- Own proc = inside one of its own module's contributions (ICF folds sit in another module's, C0018). Main run = run with most own-proc bytes.
- Edges: pin a range end by an LIS anchor (C0011) at the run edge, or by the adjacent run's edge anchor (the cut between two units is known if either side's edge proc is an anchor). Otherwise unpinned; report the edge proc's class.
- Anchor-window resolution for an ambiguous edge proc (1.3/T10.c3): complete hit list (not capped), exactly one hit in the retail gap between its nearest LIS anchors, and that hit == proto-offset prediction from either anchor. Released 39 of 559 edge procs (428 had no hit in the gap). Pinning an edge widens a fallback range, so re-run the consistency check after resolution: it can flip other units too (7 here).
