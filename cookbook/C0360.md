# Strength-reduced loop base field: stand-in reference to the element; NAME tag window

- When cl strength-reduces a loop over an array of structs, it folds ONE field's offset into the base/induction
  register (retail `lea ecx,[ebp-0x5c]` = &points[0].z). Statement order, member stores, a 3-arg ctor, reordered dot
  products and even deleting statements never moved it. A `// !FAKE:` stand-in reference to the element,
  `const Vector3& p = points[i];` read through p.x/p.y/p.z, moved the base and matched ZoneNode::RenderChunks
  0x000C4CB5 (5.2 T12.c29). FanBoatWake::Update: `WakeVertex& p = _wakeVerts3[n + 1];` moved it too (95.62).
  Check retail's listing for the folded field first (va_dis dis).
- Unguarding a row runs the locals check: a non-PDB local name (`dir`) fails; rename to the PDB/placeholder name.
- provenance_lint `func_ident` reads at most 7 lines after a `// NAME:` tag: a guarded draft's best-comment block
  between NAME and the definition longer than ~5 lines fails `no identifier found for the NAME tag`. Keep best
  comments to <= 4 lines (5.2 T12: BeepState.cpp:806).
