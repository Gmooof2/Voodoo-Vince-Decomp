# Declaration from the mangled name: access letter, template rows

- Access letter after `@@` decides the declaration: `Q` public, `I` protected, `A` private (`AAE`/`QAE`/`IAE` thiscall; `QBE` const). Wrong access -> `match_one` refuses: "symbol not defined in <unit>.obj" (rank 19 `?VinceOnUpperFloor@DinoBossMain@@AAE_NXZ`, first attempt rc 2).
- Template function row `??$NAME@U<T>@@@@...`: emit it with an explicit instantiation in the unit, `template void RELEASE<D3DDevice>(D3DDevice*&);`, under its annotation lines.
- A static D3D wrapper method (`D3DDevice::Release`) is written as an inline that calls the retail import (`D3DDevice_Release`); the PDB gives the class, the import name gives the callee (D78).
- Trap: a wrapper whose retail inline compiles to nothing (`Direct3D::Release`, PDB static, no body source) has an unknowable return value; T12 kept `RELEASE<Direct3D>` under NON_MATCHING although it matched with `return 1;` (D78 question).
- Header inline rows (`MoviePlayer::IsActive`) need an unmatched caller in the unit to be emitted out of line: skip until the caller is drafted.
