# C0190 — /O1 eax-reached returned temp: only an inlined reference parameter gave it; check PDB locals first
tags: msvc,cl,o1,inline,eax,temp,d78,pdb_types,matching · date: 2026-11-01 · phase/task: 4.2/T3 · origin: T3.c1 inline helper levers

Use: a /O1 function whose retail reads a returned struct's fields through eax, and the draft reads them from a stack slot.

- Superseded in part by C0191: a pointer local also keeps the reach, and passes with no helper.
- In these runs the eax reach into a returned struct appeared only from an inlined function's reference parameter. A `const T&` local bound to the same call was folded to the temp's stack slot, so hand expansion did not reproduce it (GetViewMatrix, GetFrontClipPlane, GetWorldFacing). Three functions of evidence, not a proof.
- So the eax-reached temp is a tell that an inline existed. Writing one is a D78 and CONVENTIONS question: see `docs/evidence/inline_helpers.md` before drafting a helper the PDB lacks.
- Run `PY tools/pdb_types.py locals <proc>` before drafting: it says which temps are not named locals, so a hand local is known to be invented before it is written.
- At /O1 /Oy, plain `inline`, `__inline`, body forms, `/Ob1`, `/Ob2`, `/Oi`, `#pragma auto_inline` and `inline_depth(255)` left the same 4 of 45 rows out of line (the helper stays a call); `/O2` and `/Ot` lose 34 of 45.

Ref: `docs/evidence/inline_helpers.md` "Results common to all 7 uses".
