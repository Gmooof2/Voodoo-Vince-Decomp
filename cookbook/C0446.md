# Disk name case drifts from the git index on Windows (core.ignorecase true)

Symptom: private gate green, fresh clone fails a layer keyed on paths (5.5 T18: provenance, 22 failures).
Mechanism: with core.ignorecase a file renamed/recreated in another case keeps the index case; git status is clean,
but tools walking disk names (`Path.rglob`, os.walk; provenance_lint.py:933) see the disk case. Any baseline they write
(config/provenance_accepted.txt) carries disk case; a clone checks out index case, so the baseline goes stale.
`git ls-files` is identical in both copies; only the disk differs.

Check (whole tree, every path component, not just suspected files): for each `git ls-files -z` path walk its
components, compare each with `os.listdir(parent)`; a name present only case-insensitively is drift.
Usage: `PY casecheck.py <repo root>`; exit 1 on any mismatch (5.5 T31):
```python
"""Compare each git ls-files path component's case with os.listdir on disk. Prints mismatches; exit 1 if any."""
import os, subprocess, sys
root = sys.argv[1]
files = subprocess.run(["git", "-c", "core.quotepath=off", "ls-files", "-z"], cwd=root, capture_output=True, check=True).stdout.decode("utf-8").split("\0")
cache, bad, missing = {}, [], 0
for f in filter(None, files):
    parts = f.split("/"); d = root
    for i, p in enumerate(parts):
        if d not in cache:
            try: cache[d] = set(os.listdir(d))
            except OSError: cache[d] = None
        names = cache[d]
        if names is None: missing += 1; break
        if p not in names:
            low = {n.lower(): n for n in names}
            if p.lower() in low: bad.append(("/".join(parts[:i+1]), low[p.lower()]))
            else: missing += 1
            break
        d = os.path.join(d, p)
seen = sorted(set(bad))
for idx, disk in seen: print(f"MISMATCH index={idx} disk={disk}")
print(f"checked {len([f for f in files if f])} files, {len(seen)} mismatches, {missing} absent on disk")
sys.exit(1 if seen else 0)
```
Run before any public cut and after renames.

Fix: rename on disk only, two-step (`mv x x.tmp && mv x.tmp X`; one-step is a no-op on NTFS); no `git mv`, the index
is already right. Then rewrite the path field of affected baseline entries to index case (LISTED file -> review task,
re-pin `verifier_lock.py write`), commit, gate.
