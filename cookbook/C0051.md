# Live build identity of a loaded XBE: three getmem u32 reads against the pinned file

- Problem: XBEH magic + initFlags at baseAddr pass on any XBE (July 2003 prototype passed, C0050).
- Move: read 4 bytes each at baseAddr+0x114 (header TimeDate), certificateAddr+0x08 (cert titleId),
  certificateAddr+0xAC (cert version); compare with `xbe_info.parse_xbe(pinned)` fields `header.timeDate`,
  `certificate.titleId`, `certificate.version`. The header region (incl. certificate) is mapped at baseAddr on the box.
- On mismatch print the field name and `wrong build`, never values (D46 output rule). Still `getmem` only (D75).
- Self-test: serve a synthetic XBE copy with TimeDate xor 1 to the loopback mock while comparing against the original:
  exit 1 and the field named. Code: `tools/xbdm_probe.py` `build_identity`.
- Not a replacement for the function sha1 checks: identity says which game, sha1 says the bytes match.
