# cl 13.10: a retail dtor with no vptr store means the source declared no dtor (compiler-generated)

Context: MSVC 7.1 (cl 13.10.3077) matching, 1.4 T9.c2, FlourSackMain::~FlourSackMain (fpo, inlined member dtors, tail jmp to base dtor).

- Any destructor the source declares (even inline `virtual ~X() {}`) stores the vptr at entry; no flag (/O1 /O2 /Ox /Ob2 /Og /Os) removes it.
- Retail dtor without vptr stores = the class (and intermediate bases) declare no dtor; members' dtors inline, the last real base dtor is a tail `jmp`.
- Don't use `__declspec(novtable)` to kill the store: it also removes the ctor's vptr store; check the ctor in retail first.
- A compiler-generated dtor is emitted only when used: in a test source force it with a scaffolding user, e.g.
  `void pin_emit(X* p) { p->X::~X(); }`, outside the compared symbol, marked as test-only.
- Control choice: a frameless function gives identical bytes under /Oy-; flip /Ob1 -> /Ob0 when inlining shapes the body.
