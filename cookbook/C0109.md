# Ghidra folds a tail-jmp target below the jumper's entry into the jumper's body

Symptom: a pinned function sits just below another function's entry; the cut relocation at the jumper's tail
`jmp rel32` names `.text` (section-symbol fallback), not the pin. ApplySymbols reports the pin `inside` a
container, and the container is the function *above* the pin, not the one before it.

Mechanism: the jumper ends in a tail `jmp` back to an address below its own entry (retail 3.2 T4:
`??1SwampScriptManager@@QAE@XZ` 0x11E90 ends 0x11EB6 `e9 aa ff ff ff` -> 0x11E65, `_Tree::_Tidy`). Ghidra
flows into the target and folds it into the jumper's body (body min < entry). No function at the target, so
the delinker has no symbol for the rel32. Do not trust a "container = previous function" guess: read the
container from Ghidra (`getFunctionContaining`), and check the previous function ends before the pin (here
FUN_00011e12 ends at its `ret 0c`, 0x11E64).

Fix (tools/ghidra_scripts/ApplySymbols.java splitAt, 3.2 T4.c3): when the pin a lies in container C with
a < C.entry and both a and C's entry are sized accepted func lines, clip C to body ∩ [C.entry, C.entry+size)
and create a. Summary field `splitBelow B`; log line `ApplySymbols: splitBelow <C> at <entry> for <name>`.
Evidence to require: the tail jmp, both pins sized, and a + size(a) == C.entry exactly.

Related: C0085 (cut spans an unsymboled tail-jump target), C0103 (func pin at row end), C0108.
Check: `name_sites.py --check-cut` FAIL 0.
