# ghidra-xbe XbSymbolDatabase / XTLID labels: how to flag them in an export

- Mechanism (ghidra-xbe src `XbeXbSymbolDatabaseAnalyzer`): runs native `XbSymbolDatabaseCLI.exe` on the XBE; each
  `LIB__name = 0xVA` line -> `createLabel(va, name, ns=<LIB> global namespace created SourceType.IMPORTED, SourceType.ANALYSIS)`.
- `XbeXtlidAnalyzer` (`.XTLID` section) uses the identical pattern; when both name the same va/ns/name Ghidra keeps one symbol.
- After auto-analysis most such labels become FUNCTION symbols (retail: 302 of 355), not LABEL: flag LABEL or FUNCTION.
- Flag rule: symbol source ANALYSIS whose parent namespace is a global namespace with source IMPORTED. Split xtlid
  (va in XTLID table) from xbsymdb; xbsymdb then undercounts the CLI's own lines by the overlap.
- Cross-check: run `os/win_x86_64/XbSymbolDatabaseCLI.exe <xbe>` directly and compare (va, ns, name) sets.
- Kernel imports: XbeLoader `createLabel(slot, name, IMPORTED)` + external ref to `xboxkrnl.exe`.
Impl: tools/ghidra_scripts/ExportProgram.java.
