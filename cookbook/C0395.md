# Row-end pin on a LAB_ inside a cut object: defsyms OTHER, never a clean re-cut

- A C0103 row-end pin at a VA Ghidra had as `LAB_<va>` (symbol class 3) inside an existing cut object makes it a function (class 2) and its body gains relocations (fields that were baked bytes now carry relocs). recut_cmp reads `OTHER bytes,relocs,defsyms` on that object (delink and .text section). A string pin the new body's site needs (C0375 round 2) adds `.rdata OTHER defsyms` (class 3 -> 2).
- M33 relocs-added cannot cover it: relocs-added applies only when relocations and bytes outside the fields are the only change; a symbol class change is defsyms.
- So cut-extent row-end pins (I60) always end in a review re-cut. Keep them out of a merged pin pass that wants the no-stop recut_proof route; re-cut them on their own and return review with the LISTED pair uncommitted.
