# Link a lone retail section at its retail layout: filler objects, not absolute stubs; /SUBSYSTEM:XBOX traps

Proven 2.3 T3 on XGRPH (digest == retail): `tools/relink.py link|check`, evidence `docs/evidence/relink.md` "One section relinked (T3)".

- Absolute-symbol stubs fail with imageBase 0x400000: LINK emits no base reloc for DIR32 to an absolute symbol, and REL32 is
  computed in PE VA space, so after the writer's uniform rebase (C0074) one of the two is wrong.
- Filler instead: Python-written COFF objects with zero-filled sections for every other linked section (retail PE VirtualSize
  and characteristics from the XBE's PE-header copy, alignment bits ALIGN_4); each cut external defined at
  (target VA - section VA) in its filler section; only a target outside every linked section is absolute.
- Object order on the LINK line (filler_pre, cut, filler_post) gives first-appearance section order = retail order + .reloc.
- `/SUBSYSTEM:XBOX` alone gives the prototype's imageBase 0x400000, 0x20/0x20 alignment, characteristics 0x10E. `/BASE` and
  `/ALIGN` are ignored with LNK4075 (+LNK4108): do not pass them.
- PE SizeOfHeaders follows the section count (0x380 for 11 vs proto 0x400); harmless, peBaseAddr absorbs it.
- Ghidra COFF export names externals `namespace::name` (e.g. `XAPILIB::_SetLastError@4`): map back via symbols.jsonl `namespace`.
- Treat any LINK output line as failure; use /OPT:NOREF /OPT:NOICF /NODEFAULTLIB /FIXED:NO, never /FORCE.
- Check: negative control (one filler symbol moved +4) must make the digest differ.
