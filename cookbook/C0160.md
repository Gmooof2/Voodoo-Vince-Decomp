Context: 3.5 T7 M3.5-2. Clone `hashes.txt` stable across 3 runs (repro + fresh, one sha256) but differs from the
working copy's in one object (SoundStreamer.obj).

Move:
1. List differing objects (line-diff the two hashes.txt).
2. Disassemble/diff the object pair: here the only change was an extern callee symbol
   (`DSOUND::IDirectSoundStream_Pause` in WC, `DSOUND::_IDirectSoundStream_Pause@8` in the clone).
3. `git log` the pin/symbol inputs for that VA (here 0x00179AD5, added in a commit at 01:05) and compare with the WC
   cut's mtime (`derived/delink/<retail>/cut.complete`, 23:23 the day before). Pin newer than cut = WC cut stale.
4. Only when the inputs are older than both cuts is it C0053 nondeterminism (FID/extern names).

Fix: rerun `delink.py --fresh` in the WC; never copy hashes across trees or force equality.
