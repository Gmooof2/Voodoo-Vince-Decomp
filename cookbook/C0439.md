# Working on the locked gate: two traps while writing controls

- Every scratch `_core` run (a control, a demo) runs the lock layer first: after ANY edit to a LISTED file, run
  `PY tools/verifier_lock.py write` before the next demo, or every run stops at `lock` and hides the real verdict.
- Self-test stdout is byte-goldened (C0389, C0438): a control must never print a value that varies per run that
  gate_golden does not mask (a scratch repo's commit sha, a temp path, a pid). Print a count or a fixed label instead.
- A gate-wide safety net (catch any Exception/SystemExit in the build-to-bytes span, consume the lanes, return) keeps
  the lanes' verdicts (D51); a try/finally with re-raise does not, since `_one` and the caller lose them (5.5 T12.c3).
