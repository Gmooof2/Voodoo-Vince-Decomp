# One output per pipeline stage; consumers read the stage that made their inputs

Problem: a later stage re-runs an earlier export (same tool, same out dir) after mutating state (Ghidra
ApplySymbols renames USER_DEFINED). Earlier readers then see different data depending on run order
(xdk_report label counts drifted after `delink.py --fresh`: xbsymdb 296 -> 79 rows), and the earlier
dir vanishes mid-run (rmtree), so concurrent readers refuse.

Move: give the later stage its own subfolder (`derived/ghidra/retail-<sha8>/applied/`), clear only it;
the parent stage's rmtree of the whole dir removes the child, so a stale child cannot outlive its parent.
Then route each reader by provenance, not by habit: tools that resolve names inside artifacts produced from
the mutated state (delinked objects -> byte_compare, coff_info) read `applied/` when present; tools that need
the original analysis tags (xdk_report, units_seed) read the parent files.

Check: before fixing, list every reader of the shared file and ask which state produced the artifact it pairs
with; T12.1 first missed that byte_compare/coff_info had silently depended on the overwrite (no-table-VA 995).
