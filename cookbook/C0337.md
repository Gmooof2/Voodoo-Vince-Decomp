# Visible Ptr<T>::operator= body stops by-value smart pointers escaping

- With only a declaration of `Ptr<T>::operator=(const Ptr&)`, by-value Ptr parameters escape to an unknown callee and the release reads `add eax,4; dec [eax]; cmp [eax],ebx`; with the template body visible in the unit (same body as SwampLoader.cpp; retail 0x000BDC97) plus the PDB-listed `SmartBase::AddRef`, it becomes retail's `dec [ecx+4]; jne` (Swamp_LoadWorld 0x000C54D0 84.66 -> 87.04). Related: C0222, C0330 (ResourceHandle operator=).
- Syntax-only rewrites (decl style, nested ifs vs goto, decl order) compile to the same IL: identical scores; spend attempts on semantics (visibility of bodies, temps, scopes).
- Scratch compiles with the retail cl in `.run/<phase>/.../probe` test loop forms without spending ledger attempts.
