# x87 operand order: alias the vector component, not the scalar (lever A limit)

- C0354's `const float& v = <scalar>` is neutral when the scalar's only uses are one ctor's three products: cl still
  folds the last product as `fmul [mem]` (5.2 T12.c26: CheckLineAgainstSphere 0x000B1F90 +0xA3, ResetLocation
  0x0010B763 +0xFC). Byte-identical probes: named-const alias, ref bound to a call temp, non-const source, member
  stores in a block, product stand-in.
- Aliasing the OTHER operand at its FIRST uses flips operand order: `const float& zz = zb.z; const float& zy = zb.y;`
  in the dot sum (`zz * up.z`) and the first cross term moved every x87 diff of Matrix::View 0x000DDC1E
  (97.14 -> 98.09). Aliases in later terms did nothing: cl keys operand order on symbol identity at first use.
- Probe driver: `PY tools/probe_form.py --flip N` (C0345 loop; flip 1-2 guards per unit).
