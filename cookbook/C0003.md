# Self-testing a git audit in a scratch repo (hook-safe)

Use: a tool that scans git scopes (worktree, index, history) must prove each detection before it is trusted (D47).

- Scratch repo under `.run/<phase>/<tool>_selftest/`, never this repo; `git init` there and run git with `cwd=scratch`.
- Strip every `GIT_*` var from the subprocess env: inside a hook git exports `GIT_INDEX_FILE`/`GIT_DIR`, which would
  point the scratch commands at the real repo. The real (non-test) staged scan does the opposite: honour an
  inherited `GIT_INDEX_FILE` (`commit -a` uses a temp index).
- Commits: `git -c user.name=selftest -c user.email=selftest@invalid -c commit.gpgsign=false -c core.hooksPath= commit`.
- History-only proof: add the planted file in commit 1, delete it in commit 2; assert history and `range c0..HEAD`
  catch it, worktree, staged and `range c1..HEAD` miss it.
- `git log --all -1 --format=%H --find-object=<oid>` returns the NEWEST commit touching the blob (the delete for an
  add-then-delete), not the adding one; use `--reverse` without `-1` and take the first line for the adding commit.
- Blob content via one `git cat-file --batch` pipe; filter `rev-list --objects --all` with `--batch-check`
  `%(objecttype)`. Compare content sha1 (hashlib), never the git blob id.
- Refusal checks: run the CLI as a subprocess with env overrides (manifest/config path) and assert exit 2 + message.
- Delete on exit: `shutil.rmtree(..., onerror=chmod-then-retry)`; Windows marks `.git/objects` read-only.
- Fixtures the audit itself refuses (magics, disassembly runs) are generated at runtime with loops/f-strings, so the
  tool's own source never holds a run and the tool passes on itself.
