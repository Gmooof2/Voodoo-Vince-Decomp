# Gate negative controls: re-run the real gate core on scratch copies

When: a verifier (gate) must prove each of its checks can fail, without a mock.
How (1.5 T5, tools/gate.py `_core` + `controls()`):
- Split the gate body into a core that takes overrides (units file, symbol tables, target dir, build dir, list, src,
  audit args; defaults = production) and returns `(rc, per-fn verdicts, global verdicts)`; the CLI wraps it.
- Each control builds scratch inputs under `.run/<phase>/gate/controls/<name>/` (removed in `finally`), calls the core,
  prints its full output (D51), and counts only if rc != 0 AND its own named check fails (not just any failure).
- Self-test exit 0 only when the positive run passes and `controls: K failed as expected of K`.
- Controls that worked here: compiler_pin control flag in a units.toml copy (objdiff + bytes fail); drop
  symbols_pin.txt (bytes provisional, objdiff 100); flip one byte in a target copy + hashes.txt; edit body_sha1 /
  xbe_sha1 in a list copy (anchor on the entry's symbol line: the xbe_sha1 text is in every entry); empty and missing
  list (N=0); extra unmarked fn; matched fn under `#ifdef NON_MATCHING`; `__asm { nop }`; audit `--paths <MZ file>`;
  stale obj planted + source removed (the wipe makes it unused); ` /Zq9` (cl 13.10 rc 0 + obj written, only D4002 by
  code fails it, C0026).
Cost: ~5 s per run (audit_public no-args dominates); 13 controls 63 s.
- Untested-but-correct path (3.5 T4): a new control fails as expected at once, so prove its teeth by a temporary gate mutation forcing that branch to pass (control must report DID NOT FAIL), revert, re-pin. A thin control: stack a second break on its plant; the old assert passes, the tightened one fails.
- Run new controls alone (teeth: `DID NOT FAIL as expected` on the unfixed tree first): `PY tests/control_only.py NAME ...` (5.1 T11).
