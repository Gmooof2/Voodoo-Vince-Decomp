# Testing a git hook from Python on Windows

- `subprocess.run(..., input=str, text=True)` turns `\n` into `\r\n` on Windows. A pre-push line then ends in `<rsha>\r`:
  `read` keeps the CR, so 40 zeros no longer match "all zeros" and the hook takes another branch (`remote sha ... not in
  this clone`). Pass stdin as bytes.
- A "blocks when no Python" case needs git and sh still on PATH, or the hook dies earlier at `git rev-parse` with the
  same rc 1. Take the git folder from `shutil.which("git")`; its parent.parent is not the Git root when PATH names
  `mingw64/bin`. Assert the block message, not rc alone (C0005).

Source: 3.6 T4, first control run passed on rc 1 with `git: command not found`; the rerun showed the message.
