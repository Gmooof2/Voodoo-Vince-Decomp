# What the XBDM wire showed on the box (retail Voodoo Vince, XBDM 1.00.5849.1)

- Greeting `201-` on TCP 731; find the box by its NIC OUI `00-0D-3A` (Microsoft) in the PC's ARP table when DHCP moved it.
- `modules` (202 multiline): `xboxkrnl.exe`, `xbdm.dll`, `default.exe`. The title is `default.exe`, not `default.xbe`.
  Fields `name base size check timestamp`, key=value, name quoted.
- The title's `modules` base/size are NOT the XBE header's baseAddr/sizeOfImage (seen: baseAddr+0xC00, size smaller
  than sizeOfImage). Never compare them; print them as info.
- `modsections name="default.exe"`: one line per XBE section, base/size == section virtualAddr/virtualSize (16 of 16,
  non-preload sections included).
- `getmem addr=0x<va> length=0x<n>` -> 202 hex lines, reads of 0x4..0x1000 fine in-game, no `??` in header or .text.
- `dmversion` -> `200- 1.00.5849.1`: a box-side confirmation of the XBDM build (title-independent).
- Known-true (XBEH magic + initFlags at baseAddr) passes on the July 2003 prototype too: it proves "an XBE is loaded",
  not "the retail XBE is loaded". Build identity needs a sha1 check (function body, or the 0x1000 header: prototype
  differs in 1069 of 4096 bytes).
- Tool: `tools/xbdm_probe.py --verify <sym>`; procedure `docs/ops/runtime.md`.
