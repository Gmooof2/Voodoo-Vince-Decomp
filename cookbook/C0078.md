# Whole-image relink from originals: two link traps and the header-region boundary

Context: link every cut section (556 objects, 547 COMDAT) in one LINK 7.10 run, zero fillers, and write the XBE (2.3 T5, `tools/relink.py check --originals`).

- Trap 1, bss alias uncovered: an alias VA inside a section's uninitialized tail (e.g. `.data` bss) has no cut object covering it -> `no cut object covers it`. Fix: extend the last object's cover range by the section's tail (vsize - rawSize).
- Trap 2, LNK2016 `Absolute symbol ... used as target of REL32 relocation`: a REL32 whose target lies outside every section (e.g. a bogus Ghidra `SUB_` target) cannot be an absolute symbol. Fix: define it section-relative in the first cut object at `(target - section VA) mod 2^32`; LINK then emits the same displacement.
- Other aliases with no filler: put them in a section-less `absolute.obj` (absolute symbols are fine for DIR32).
- XBE header region (PE-header copy at 0xC00, TimeDateStamp, Rich, INIT/.XBLD/.tls/.reloc dirs) is not linkable from cut objects: take it from the pinned retail image, rewrite every section-table field from our link (`xbe_write.write_section`), check the entry. State it as the claim boundary.
- Result: 16/16 section digests and whole-file SHA1 equal retail; .reloc size differs (info only, not in the image).
