# A pin route that leans on another row: test that row's bytes, not its fails list

When: a pin_rows route names row A from evidence inside row B (5.5 T4: creationFunc A from the push in RegisterMe B,
tag `proto-pdb-public+registerme-twin`, route `twin`).

- B's own route already checks A's name (callee-name rule). If A's route required "B has no fails", a wrong A makes B
  fail, A then finds no caller, and both rows report a reason that hides the cause. Evaluate B independently instead:
  masked-equal body plus its own discriminator (`State.registerme` literal check), ignoring `fails`.
- Count agree and conflict both ways: (proto dest in A's protos) != (retail dest == A's VA) is a conflict
  (`twin-differs`); no site at all is `no-registerme-site`; conflict wins when both apply.
- Run it where corr_route runs (after every row's route), since it reads other rows.
- Control: retag a real row in memory (kw `direct`) and plant another class's name; a pin-file copy adds
  `dup-name-two-vas` fails and breaks an exact expected-fails compare.
- Locked table for hand rows: `config/pin_hand.txt` (VA, name, class, pointer), fail `hand-row-not-listed`; a moved-row
  plant picks its target at run time (an unnamed function start no site reaches).
- Result 5.5 T4.c1: 5 of 5 T26 twin rows pass retagged; 13 of 13 census-F shifted names fail.
