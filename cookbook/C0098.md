# C0098 — Patch a tool's module attribute via a private namespace, not the shared module
tags: python,controls,monkeypatch · date: 2026-10-27 · phase/task: 2.6/T6 · origin: T6.c1 C2.1-1 driver

# Monkeypatching a module attribute of an imported module patches it for everyone

Context: a control driver forces a tool's cleanup to fail, e.g. `xdk_report.shutil.rmtree = f`.

Trap: `xdk_report.shutil` IS the shared `shutil` module object; the assignment replaces
`shutil.rmtree` process-wide, so the driver's own `shutil.rmtree` (scratch cleanup) also fails.

Move: give the tool its own namespace first, then patch that:
    import shutil, types
    ns = types.SimpleNamespace(**{k: getattr(shutil, k) for k in dir(shutil) if not k.startswith("__")})
    ns.rmtree = f
    xdk_report.shutil = ns
Restore with `xdk_report.shutil = shutil`. Same applies to `os`, `subprocess`, etc.
