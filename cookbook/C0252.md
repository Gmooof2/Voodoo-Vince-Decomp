# Profile a locked tool: scratch driver, cProfile, timeline markers, one plain run to calibrate

Problem: a locked verifier (relink.py, 248-270 s at 1,398 rows) had to be split by phase without editing it.
cProfile alone mis-ranked the phases: per-call overhead inflates code with many tiny calls ~9x
(`ours_before`'s 256M `Path.__eq__` calls: 197 s profiled, ~22 s plain) and barely inflates long genexpr scans.

Technique:
1. A scratch driver under `.run/<phase>/` imports the tool and calls its library entry (here `relink.gate_check`)
   with the same inputs as the gate (absolute paths: the tool calls `relative_to(REPO)`).
2. Wrap module-level callees (`setattr(mod, name, wrapper)`) to log `perf_counter` at entry and exit; patch
   `subprocess.run` and `Path.write_text` (filtered by file name) for external steps. Calls through module globals
   pick the wrapper up; nested functions cannot be wrapped, but cProfile names their genexprs by line.
3. Run it twice under `python -m cProfile -o` (background shells) for the function split, and once plain for the
   true seconds per marker phase. Rank by the plain run's markers; use cProfile only to name the hot lines.
4. `next(x for x in seq if lo <= v < hi)` called per symbol over a list that grows with the matched count is the
   usual superlinear cause; list membership on `Path` objects (`p not in list`) pays `_str_normcase` per compare.
   Exact fixes: bisect on sorted disjoint ranges, a `set` beside the list (Path hash agrees with ==).

Result (4.4 T2): LINK 1.8 s, write 0.5 s; 223 s in two interval scans, 22 s in list membership; sizing for T3.
