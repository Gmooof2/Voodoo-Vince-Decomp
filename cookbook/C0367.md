# XBE section flags: .data and .rdata carry the exec bit, so "non-exec" selects no data section

In the retail XBE `.rdata` has flags 0x6 and `.data` 0x7: both carry `proto_map.SEC_EXEC` (0x4). A scan that picks
"data" sections as `not flags & SEC_EXEC` therefore skips both and finds nothing (5.3 T1.c2: 0 of 200 vtable-slot
bodies found; 163 of 200 once `.rdata` and `.data` were taken by name). Pick data sections by name, or scan every
section and label hits by section name. Checking the scan on a set with a known answer (vtable slot bodies) exposed it.
The same scan over every section is the cheap way to ask "what references this VA at all": `bytes.find(pack("<I", t))`
per section; 5.3 T1 found every creationFunc body referenced exactly once, by a code immediate in `.text` (a
`push imm32` in its RegisterMe ctor), which no rel32 call index sees.
