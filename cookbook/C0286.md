# Account for known check failures by exact site, with a stale check

Problem: a check (here `name_sites --check-cut`) fails on sites that a ruling deliberately left (pins disabled under R1/R8, names left unpinned). The setup guide promises exit 0, so a walk stops on it; accepting rc 1 would hide a new failure.

Move:
- List each accepted failure keyed by its exact site (row VA, offset, target), never by target alone: another site at the same target still fails.
- Each entry has a reason and a pointer (the DISABLED note line, the commit, the validation record).
- A listed site that no longer fails prints `STALE` and gives exit 1, so the list shrinks as pins come back.
- The summary line prints `accepted A, FAIL F` and groups accepted sites by reason.
- Controls in scratch: a site taken off the list fails (rc 1), and a made-up listed entry is stale (rc 1).

Evidence: 4.4 T18.c2 (af0a5502): 21 sites, 6 reasons; green `accepted 21, FAIL 0` rc 0; both controls rc 1.
