# Unit range from disasm-verified pins when the unit has no LIS anchor

Problem: a game unit whose main run has no LIS anchor gets no retail range (`no range: no anchor in main run`).

Move (3.2 T9, `units_seed.py --route --class no-range`):
- Anchor = a main-run proc whose PDB public is in the 3.1 symbol pins AND whose retail bytes are masked-equal at the pin VA.
- All pin anchors must share one delta (retail VA - proto VA); differing deltas -> keep.
- Edge = `pin` when the run's first/last proc is itself pinned; else byte chain (C0106) out from the first/last pin.
- Accept only: range in one exec section, no identical copy of another owner inside, no overlap with existing ranges,
  outside identical/near-identical copies explained.
- Kept units get `delink_reason` with `searched:` (LIS anchors, pins of N procs, identical hits-1 copies + deltas) and `fails:`.

Trap: `units_seed.py --check` requires units.toml order = ranged blocks by text_start, then unranged by index.
A released previously-unranged block must be moved into the ranged section, or --apply refuses to write.

Result 3.2: 16 game units -> 1 released (Particle#451 pin/pin), 15 kept (14 had no pin; SwampTextureResource pin chain broke).
Identical hits-1 non-LIS copies as anchors were NOT used: a new evidence class, a plan change.
