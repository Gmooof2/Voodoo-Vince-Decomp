# C0189 — Test a pin with no bytes: a pin-independent (proto dest, retail dest) site index
tags: naming,pin,site-corr,bss,control,proto_map,check · date: 2026-11-01 · phase/task: 4.2/T3 · origin: T3.c2 pin-row check prototype

Use: testing a pin row, a name with no bytes to compare (bss, site-corr), or a check that must not trust the pin file.

- Index, independent of the pins: every `identical` proto_map function with one target (5080 at 4.2); each mask outside itself gives a pair (proto dest, retail dest). Build 0.5 s, no source read.
- `agree`: the pair (P(name), VA) is in the index. Conflict: P(name) reaches another retail VA, or VA is reached from a proto dest whose publics exclude the name.
- It caught T1's bss plant (`?g_swamp` -> a real C-linkage public, source following), which passes the gate, on a VA with no bytes. All 70 bss pin rows have agreeing sites, so each is testable.
- A real conflict is not always a wrong name: retail holds two copies of a literal, and a proto fold can reach several retail VAs. Report both sides; 8 rows do so today.
- No site, no verdict: 14 rows, and a byte twin nothing identical calls passes (39 B `creationFunc`). Bytes alone are weaker than they look: 496 func rows have a same-masked-body public at another proto VA.
- The pairing can come from symbols.txt plus the PDB instead of `functions.jsonl`, which is unpinned: 4,684 pairs, 0.67 s, 47 rows change site class, the same verdict on every plant.
- Verdict a one-row plant by new row fails against a pristine run, not by the absolute count: today's file already has fails.

Ref: `docs/ops/validation.md` "4.2 Pin-row check, sizing".
