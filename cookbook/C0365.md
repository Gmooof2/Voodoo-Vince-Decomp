# C0365 — Free Vector3 operators with no PDB record: 3-float ctor, member-store local, comma pointer locals
tags: msvc,cl,o1,vector,operator,inline,d78,d117,matching · date: 2026-11-07 · phase/task: 5.2/T20 · origin: T20.c1 six rows

Use: a matched or draft row whose retail inlined a free binary Vector3 operator (`a + b`, `a - b`, `v * f`) that default.pdb does not record (D78, D117). PDB Vector3 members: ctor(), ctor(f,f,f), ctor(ulong), [], Set, +=, -=, *=(float), *=(Vector3), /=.

- `v * f` -> the PDB 3-float ctor `Vector3(v.x * f, v.y * f, v.z * f)`: the operator body verbatim, same bytes (LevelLoader::LoadSettings 0x001011E5, first try).
- `a - b` stored to a member -> a named local filled by member stores, then copied: `Vector3 v0; v0.x = a.x - b.x; v0.y = ...; v0.z = ...; dst = v0;` (C0227). Storing components straight into `dst` was 95.14: the frame lost the temp's slot (FFly{Point,Sphere,Ellipse}Surf::Spawn).
- Operator applied to call results inside one expression -> keep one expression: a comma expression taking C0191 pointer locals to each operand temp, ending in the 3-float ctor: `dest = (..., v1 = &Vector3(tmp), p = &pad->GetWorldPosition(), Vector3(v1->x + p->x, ...));`. Split statements 88.0; `Vector3(tmp) += pos` 99.75; `-=` on the temp 97.12 (FanBoatMain::GetParkingDest 0x0002E31B, Activate 0x000305AF).
- Operand order follows retail's call order; hoist an object pointer (`FanBoat* v2 = GetBoat();`) when retail loads it before the first call (95.29 without).
- Find the users first: guard the free operators and run the full build; each C2676 line is an unguarded user.
