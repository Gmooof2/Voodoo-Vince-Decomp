# Scratch clones on Windows: clone with core.autocrlf=false when tools hash tracked files

Use: a scratch clone of this repo for rehearsing hooks or tools that verify tracked files by hash.

- Default Windows `core.autocrlf=true` checks text files out as CRLF; a tracked sidecar hash of an LF file
  (`config/inputs.manifest.sha1` over `inputs.manifest.jsonl`) then mismatches and the tool refuses (exit 2).
- `git clone -q -c core.autocrlf=false <repo> <dir>` keeps the bytes the main working copy has.
- Gitignored local config is absent in a clone: point the tool at the main repo's copy by env
  (`AUDIT_PUBLIC_CONFIG`), never by copying it into the clone.
- Strip `GIT_*` from the env before running git in the scratch dir (C0003).
