# Measure what a naming ruling frees: classify blocker sites, ask which rows empty out

Use: before promoting names or weighing an evidence rule, to learn how many rows it really frees.

- Class every blocker site (`family_census.make_row`'s test) by owner pin and status; a row is freed when every blocker's class is in the set. Alone and cumulative differ widely (gSettings 16 pool rows alone of 57 carrying it).
- Count targets by owner pin as well as raw VA: member sites inflate raw VA (bss 284 raw, 69 owners).
- "Sole blocker" has two counts: sole unresolved (`resolved` None) and sole of any status. `pool_buckets` targets count the first: 0x02DE9D 15 against 5 + 5; SoundStreamer::Play 3 against 0.
- Tools write docs when run as programs: import `family_census.load/populations`, `pool_buckets.assign`, `name_sites.promote_route` and stay in memory. `promote_route(img, pubs, pins, acc)` copies `acc`, so a hypothetical accepted set is just a bigger dict; hash the tables at start and end.
- Replaying `check`: clear `name_sites.DOWN` per call, test `masked_equal` first, cross-check the split against `check`'s verdict.
- A count of zero needs a control: swap two pins' prototype VAs and the disagree detector must fire (bss: 0 against 74 each). The zero also carries a selection: `resolve` already kept conflicting pins out.
