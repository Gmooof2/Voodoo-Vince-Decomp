# Global load placement: pointer stand-in assigned inside the call's object expression

- Retail loads a global object pointer (g_particleManager) AFTER an argument's string-temp ctor and BEFORE another
  argument's virtual call; a plain `g_particleManager->AddOneShot(..)` loads it elsewhere.
- Match (5.2 T12.c28, SewingBulletMain::FrameTick 0x0004137B): `// !FAKE:` pointer stand-in assigned in the object
  expression: `SwampParticleManager* p; (p = g_particleManager)->AddOneShot("bulletMiss", bullet->GetWorldPosition());`
  -> cl loads the global into edi at retail's point. A comma form inside the argument did not match.
- Inlined free operators held on the x87 stack across a statement (VinceSwing::FreeFall) have no hand-form twin:
  member stores, ctor temps, unnamed temps, reference stand-ins and Set/`*=`/`+=` all move `elapsed` into an x87
  register (97.625 at 20). Treat as D78-barred.
- objdiff can omit a function's score from report.json (0.0 printed) while the build is real (FireFlyResource ctor
  0x000D1A27): read va_dis obj for the true first diff.
