# recut_cmp plant: update the after-cut copy's hashes.txt line, or the plant is never compared

Use: a negative control for `tools/recut_cmp.py PRE CUR` (or any compare that selects "changed" objects by a hash list).

- recut_cmp picks the objects to compare from the `hashes.txt` lines that differ between PRE and CUR. A byte flipped in a copied `.obj` with the copy's `hashes.txt` left as it was is skipped: `changed already-delinked objects: 0; OTHER 0`, rc 0, so the control "passes" with nothing tested.
- Plant: change the object (one `.text` byte outside every relocation, or one relocation's type word), then rewrite that object's sha256 in the copy's `hashes.txt`. Want `OTHER bytes` / `OTHER relocs`, rc 1; an unchanged copy rc 0.
- The real path depends on delink rewriting `hashes.txt`; a re-cut that left it stale would hide a changed object. That is a review item (D121 path), not a plant fix.

Evidence: 4.5 T5.c2, logs t5c2_recut_text, t5c2_recut_reloc, t5c2_recut_same, t5c2_recut_text_stalehash (`.run/4.5/logs/`).
