# Constants listed as abs sites: the prototype .reloc decides; and what a caller xref cannot add

- Retail XBE has no reloc table, so candidates/mask_proc mask any dword in the image range as an `abs` site
  (push-buffer values 0x403xx, image base 0x10000). The prototype default.exe has `.reloc`: a retail abs mask whose
  proto offset has no mask, no `.reloc` HIGHLOW entry and equal raw dwords is a constant, not an address.
  `name_sites.py` (3.1 T6.c1, `Images.match`) keeps such rows identical and files the site as residue `constant`:
  proto-mismatch fell 359 -> 17 sites and 23 more pins came out of the rows it freed.
- Caller xref (C0059) as a second pass over residue: when pool rows already map the target to one prototype address,
  every other caller lands on the same proto target and the same publics. It adds nothing for multi-public (folded
  code, D44: one VA cannot carry per-site names) or no-public (static) targets; only proto-mismatch targets can gain.
  3.1 T6: 29 targets blocking >= 3 rows examined, 0 pinned.
- Trap: candidates resolves `site-corr` pins too (`resolved` non-null) but still fails the reloc check; pool_buckets
  then files rows with no unresolved site under reloc-code (`any()` over an empty list is False): 247 of 297 in T6.
- Trap: 80 of 2721 pinned sites have no relocation at that offset in the cut (Ghidra made no reference there),
  although the function symbol exists; check those rows' cut with llvm-objdump (C0063) before matching.
