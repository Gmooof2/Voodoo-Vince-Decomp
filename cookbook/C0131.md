# Pin-only func rows need intra-unit REL32 from the delinker

Symptom: after adding pins that name new func VAs (only in `config/retail/symbols_pin.txt`), candidates shows c0035
`intra-unit rel site(s) without a target reloc` on those rows and `name_sites --check-cut` FAILs with `cut relocation
names None`; pool_buckets REFUSES the rank (no bucket covers c0035).

Mechanism: `tools/delink.py` `_func_rows()` fed `_add_rel32` from `symbols.txt` only; Ghidra emits no relocation for
intra-unit calls, so units whose callee is named only by a pin had none.

Fix (3.3 T9.c3): `_func_rows()` also reads sized `func` rows of `symbols_pin.txt` (skip size `-`/0, dedupe by VA,
symbols.txt first). `delink.py --fresh`, `relink.py cut`, `candidates.py --write`: rel32 added 1385 -> 1666,
c0035 4 -> 0, check-cut FAIL 2 -> 0, gate green.

Any task that adds sized func pins at new VAs: re-run delink --fresh and expect REL32 counts to rise.
