# Parallel coders: one scratch folder per coder, never a shared parent

Problem: three parallel coders were each told "scratch under .run/5.5/t6/". One ran `rm -rf .run/5.5/t6` at cleanup and
deleted another coder's scratch clone while a gate was running in it (rm stopped only on the held run.lock).

Move: name a distinct scratch folder per coder in each brief (`.run/<phase>/t<n>c<k>/`), and tell coders to delete only
the folder they created, never a shared parent. On Windows a held msvcrt lock file makes `rm -rf` fail part-way, which
leaves a half-deleted tree, not an intact one.

Detection: the deleting coder saw "Device or resource busy" on `<clone>/.run/<phase>/gate/run.lock`.
