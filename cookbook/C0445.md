# Original header paths and line numbers from the prototype PDB's C11 line info

When: placing declarations in headers (readability stage 2), or checking which file and line a proc came from.

- Module streams (pdb_info `read_streams`, stream = modules.json `stream`) end with C11 line info after the symbols:
  `u16 cFile, u16 cSeg, u32 baseSrcFile[cFile], (u32 start,end)[cSeg], u16 seg[cSeg]`; per file at L+base:
  `u16 cSeg, u16 pad, u32 baseSrcLn[cSeg], (u32 start,end)[cSeg]`, then the file name as a NUL-terminated string
  (not length-prefixed in this PDB); per block at L+baseSrcLn: `u16 seg, u16 cPair, u32 off[cPair], u16 line[cPair]`.
- Find L by scanning even offsets for a header whose file names all start `d:\` (symbol-walk stop is unreliable).
- Map a proc (modules.json `procs[].off`) to the file whose range holds it: inline bodies land in their header
  (e.g. an inline dtor at `fogzone.h:23`); inlined callees are attributed to the caller's line, not their header.
- A header the PDB never names (no inline emitted from it) has no recorded path: name it for its PDB class and say so.
- Retail strings hold only `__FILE__` headers (creationFunc `new`), far fewer than the PDB.
- Scratch readers: 5.5 T17 `.run/5.5/t17/modlines2.py <stream>`, `procfiles.py <name regex>` (not kept; rebuild from above).
- Output is PDB-derived (D46): cite paths in comments, never commit dumps.
