# Source-vs-PDB name census: heuristic C++ parse false positives

Use: a census (or a future lint check) of names declared in src/ (members, methods, typedefs, params, enumerators) against default.pdb name sets, reusing provenance_lint's Pdb (`full`, `member_of`, `typedefs`, `locals_of`) by import (C0163).

Six false-positive kinds, found by hand spot-checks of 5 hits per kind (5.5 T3.c1), each to be handled before trusting counts:
- `operator->`: provenance_lint `strip_templates` drops the `>`; special-case operator names before stripping.
- Template ctor/dtor member names (`Ptr<X>`): compare the bare class name.
- Anonymous-union members: owner is the enclosing class.
- `operator=` declarations misread as data members.
- Conversion operators: the PDB spells `operator struct X` / `operator class X<class Y>`.
- `sizeof(...)` inside an array bound misread as a method declaration.

Limits that stay: no base-class lookup (STL members flattened from `_String_val`, `_Vector_val`, `_Tree_nod` bases look absent); overloads share one PDB locals set; declarations with no PDB proc cannot be checked (2126 in 5.5); function-local classes and NON_MATCHING arms not parsed.

Also: a file-scope `!FAKE` label reworded in place (outside any FUNCTION extent) shows as a fake-diff removal under `--diff` (5.5 T3, FrontEndUI.cpp; C0169).
