# Free a fold-VA template row other units call by another alias: verbatim alias body per caller, decl-only for the row's own name

- Wall: matching one alias at a fold VA (ResourceManager<VertexShaderResource> ctor 0x000C1028) makes it a row hole; other units' externals to other aliases at that VA (`??0?$ResourceManager@VRumbleResource@@...`) are refused `lies in a replaced range` (relink.py:1024-1074; row holes never take a weak external). 4.3 T11 b2.
- Fix 1 (C0231): each caller unit gets the real class layout and the verbatim template body, so it emits its own alias as a byte-equal COMDAT; it lands at the pin VA and `same()` (relink.py:1265-1291) merges it into the row as a fold duplicate (names differ, both func pins at that VA, relocs equal by target VA; shared callees pinned: `_Init` 0xBE1A0, `insert` 0xBFC67, `_Inc` 0xECEA5). Six caller units: RumbleResource, SwampAnimationResource, swampfireflyresource, swampmodelresource, SwampMaterialResource, swamploader.
- Fix 2 (C0154): `same()` never merges a copy carrying the row's own name (`our ranges overlap at 0x000BE119`, SwampLoader's OutputContents<TextureResource>): that caller gets a decl-only explicit specialization so the call resolves by name to the row.
- Order trap: the forms are green only once the rows are listed; unlisted, the unit's referenced COMDAT is extra code (`.text vsize ... does not give XBE`). Test the listed state with a scratch matched list (`matched_set.py add` into `.run/<phase>/ms.toml`) and `relink.gate_check` on a fresh build before the finish.
