# Ghidra body holes: code reached only through data gets no relocs in the delinked cut

Problem: objdiff < 100 on a byte-identical function, with the mismatched instructions all in one block whose target
operands show as raw values (`mov eax,[0x2369cc]`, `call 0xfffcd504`). Seen 2.2 T9 on `main` 0x000E0BB0: SEH filter
and handler blocks are referenced only from the .rdata scope table, so Ghidra's function body (35 of 0x3C B) skips
them, and the delinker emits code relocs only for instructions inside a function body (C0034).
Check: `PY tools/coff_info.py --check-xbe <cut obj>` lists no reloc at the hole's sites; `functions.jsonl` body size
< symbols.txt size with bodyMax at the end (a hole, not a tail; tails are C0070's).
Fix (tools/ghidra_scripts/ApplySymbols.java `fillHoles`, rename branch of a `func` line): hole = [VA, min(bodyMax,
VA+size-1)] minus the body; walk it in address order, skip defined data and bytes in another function, disassemble
each undefined start, add the instructions wholly inside the hole to the body (`setBody(union)`). Prints
`ApplySymbols: hole <name> at <va> instrs N` and `holes H instrs I` on the summary (delink.py APPLY_RE).
Result at retail-2953b782: `holes 56 instrs 763`; main gained DIR32 g_swamp at +0x18 and REL32 StopRecording at +0x26;
byte_compare --self-check 1893/1893, relocscan 0 unrelocated of 807, gate 22 of 22 unchanged before the new match.
Use: the 55 other hole functions (names in the fresh run's ApplySymbols script log) are SEH or data-reached code;
their targets are now complete. Defined data inside a body (jump tables) is skipped, never disassembled.
