# cl 13.10 EH class as seen in retail: SEH frame, C++ EH stub, which relocs to name, which controls pin

Context: VS .NET 2003 cl 13.10.3077, `/O1 /Oy`, retail default.xbe; 2.2 T9 `main` 0x000E0BB0 (SEH, matched) with
1.4 T9 `std::_Uninit_fill_n<Vector3*>` (C++ EH, C0030) for the other half.

Tell which EH it is from the first bytes:
- SEH `__try/__except` at /O1: `push <frame bytes>; push <scope table>; call __SEH_prolog` ... `call __SEH_epilog; ret`.
  Scope table = 12 B per try in .rdata: {enclosing level (-1), filter, handler}; filter and handler are code inside
  the function's extent (main+0x17, +0x2D), reached only through that data. `/O2` inlines the frame (0x3C -> 0x67 B).
- C++ EH at /O1: `mov eax,<__ehhandler$fn>; call __EH_prolog`; the `__ehhandler$fn` stub (`mov eax,<FuncInfo>; jmp
  ___CxxFrameHandler`, 10 B, static, `.text$x` ASSOCIATIVE) sits past the body in retail (fails candidates bodymax,
  C0070); FuncInfo magic 0x19930520. `/EHa` keeps the try-exit `or [ebp-4],-1` store; `/EHsc` drops it (C0030).
Relocs symbols.txt lacks, and what they are named (pin in config/retail/symbols_pin.txt, evidence compiler_pin.md):
- `__SEH_prolog`, `__SEH_epilog`, `__except_handler3`, `__EH_prolog`: prototype PDB publics; map to retail by the same
  call offset in proto and retail callers plus equal spacing between the CRT routines (C0059 xref chain).
- Scope table / FuncInfo: compiler statics `$T<n>` (no PDB symbol). Pin under the exact `$T<n>` our object emits
  (`match_one --listing`: `$T318 DD 0ffffffffH`); objdiff and byte_compare resolve by name; renumbers if the source
  changes before it (the gate fails visibly; re-pin). `__except_list` = CRT absolute 0.
