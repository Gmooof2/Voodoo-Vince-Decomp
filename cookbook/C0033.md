# C0033 — objdiff 0% on a matched switch fn: delinked target exports Ghidra caseD labels
tags: objdiff,delink,ghidra,switch,coff · date: 2026-10-25 · phase/task: 1.5/T4 · origin: T4.c1 self-test SetState

Problem: objdiff scores a byte-matching function 0% (no `fuzzy_match_percent` in the report) and sizes it far
below its symbols.txt size.
Mechanism: the delinked target (`derived/delink/retail-<sha8>/<unit>.obj`, one `.text`) carries Ghidra's switch labels
`switchD_<va>::switchD` and `switchD_<va>::caseD_<n>` as class 2 (external) symbols inside the function's extent.
objdiff ends a function at the next symbol, so `?SetState@VinceDropsInCutscene@@EAEXH@Z` (0x6C4 B) became 0x1C B
(0x474 to the switchD label at 0x490) and never pairs with our 0x6C4 COMDAT. `byte_compare` reads the XBE, so it
still says `match`.
Check: `PY tools/coff_info.py <target.obj> | grep -c caseD_`; 13 of the 143 retail-2953b782 targets carry them.
Fix (T11, 1.5): `delink.py --fresh` post-pass rewrites the storage-class byte of in-extent class-2 Ghidra labels to 3
(static) in place; objdiff does not end functions at statics (SetState back to 0x6C4) and byte_compare's resolve
already accepts in-extent class-3 statics, so class 3 over 6 (LABEL). Never tune the gate's objdiff threshold.
