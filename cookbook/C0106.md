# Unit edges by byte chain; outside procs as moved COMDATs

Problem: a unit seeded from the prototype PDB (C0020) is refused for delink because (a) its edge is
`unpinned-ambiguous` (edge proc's masked bytes hit many places, e.g. a 60-B `X::RegisterMe::RegisterMe`, hits capped
at 32) or (b) `inconsistent: N procs outside range` (a main-run proc's retail copy lies elsewhere).

Edge, `chain` class (units_seed EDGE_OK):
- Start from the unit's own LIS anchor nearest the edge (C0011). Walk the main-run procs toward the edge; each must be
  masked-equal (`name_sites.Images.masked_equal`, proto .reloc masked) at its proto-offset-predicted VA, and be the
  only masked copy in the retail gap between its bracketing LIS anchors (scan the gap uncapped, or the gap is exactly
  filled by the chain). Edge = predicted end of the last proc.
- `chain-neighbour`: the chain end equals the start of the adjacent unit's LIS anchor (or a `disasm-verified` pin of
  its proc): closed from both sides. Strongest form; prefer it.
- A prototype offset alone never fixes an edge (D78): the offset prediction counts only with equal retail bytes there.
- A `boundary` pin proves a function start only: far side of a chain, never ownership.

Outside proc, `moved` class: the single retail masked copy (proto_map identical, hits 1) lies between two LIS anchors
owned by one other unit. MSVC keeps a template/inline COMDAT from the first obj in link order, so in retail it is that
unit's contribution; our unit simply does not contain it. Explained; range unchanged.
Not explained by this: copy in a gap between units, copy bracketed by two different units' anchors, copy starting
inside a Ghidra function body (decoy hint). A gap copy may still be a neighbour's chain end: check that first.

After any edge change re-run `units_seed.py --check` (C0020: a widened range can flip neighbours); the newly covered
procs must be the chain's own.

Tally (3.2 T1, game units): 40 inconsistent-only units, 78 outside procs, 60 moved; 20 end-unpinned units, 18 chains
byte-equal, 2 broken (proc changed in retail). Route and evidence: `docs/evidence/units.md` "Unit-edge route (3.2 T1)".
