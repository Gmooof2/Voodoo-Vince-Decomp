# C0176 — PROTOTYPE lines come from the proto map, never from an earlier plant
tags: annotations,prototype,proto-map,verify,controls · date: 2026-11-01 · phase/task: 4.1/T4 · origin: T4.c1 wrong protoVA in T2 plant

A number in an old plant or evidence script is a claim. 4.1 T4.c1: T2's FOLDED plant used PROTOTYPE `0x00463A32` for `_Construct<Matrix, Matrix>`; `derived/proto_map/retail-xbe/functions.jsonl` has no such row, the real one is `protoVA 0x00463A48`, class identical, `names` holding both instantiations, target `0x00077A04`.

Before writing a PROTOTYPE line: look up the row by target VA in the proto map, take `protoVA` and `class` from it, check `names` holds the function. The lint and `annotations.py --check` take any well-formed address, so a wrong one stays green.

A control that anchors on exact label text (`prov-d66-pdb-volatile`, `BeepAlloc.cpp:104`, `:107`) errors as DID NOT FAIL when that label is reworded: read it as a stale control, not a loosened check.
