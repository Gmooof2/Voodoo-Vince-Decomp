# Route-tool controls in memory: one Route, copy.copy per control, teeth by running them before the fix

When: a decision tool (units_seed `--route`) needs negative controls (C0036) but its inputs are two binaries, the
proto_map rows and units.toml, loaded once (~30 s) and never to be written by a test.

Move (5.2 T2.c1, `units_seed.py --controls`, `CONTROLS = [(name, fn(route, seed))]`):
- Load and build one `Route`; warm its shared caches (`chain_pv()`) before any copy.
- Each control takes `copy.copy(route)` and replaces only the dict it mutates (`owner`, `byva`, `pins`), or a
  `dict(unit, _main=dict(...))` copy of one seed unit with one proc changed; then calls `decide()` and asserts the
  expected KEEP/why or note text. No file edit, no `--apply`.
- Real data is a fine plant when it already shows the fault (Whammy#460's own-anchor stray for O11); synthetic
  plants mutate one condition each (both bracket anchors handed to one other unit, a proc length past the upper anchor).
- Teeth: write the controls first and run `--controls` on the unfixed logic (every line `DID NOT FAIL as expected`,
  kept in the coder log), then fix, then `controls: K failed as expected of K`. A control added after the fix proves
  its teeth by a reverted mutation of the check it guards.
- Output line and exit mirror the gate's self-test (`controls: K failed as expected of N`, 0 iff K == N).

Trap: `copy.copy` shares every dict; a control that mutates a dict without replacing it poisons the next control.
