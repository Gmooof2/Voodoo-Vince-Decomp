# Near-lane change class: member offset shift (retail class grew, body unchanged)

- Seen 3.4 T5.c1 in 13 of 18 lane rows (9 matched): the body is the proto body; only disp8/disp32 member offsets differ
  because retail inserted members above them. Examples: HUDUI +4 from proto 0xEC up; Vince +0x10/+0x14/+0x30, _maxSkulls
  0x3F0->0x404; Critter _defaultIdleAnim +0x10, a bool 0x252->0x260; SoundStreamer field 0x64->0xDC.
- Tell: diff proto vs retail insns of the row: same opcodes/order, only `[reg+disp]` values differ, all by the same
  delta above some offset. Masked identity misses it (disp is not in-image), so sim sits 70-97.
- Recipe (D78): declare a retail-layout class: PDB members below the insertion point, an opaque `field_<off %X>` byte span
  covering the unknown inserted bytes, then the members the row reaches at their retail offsets, each with a
  `// proto 0x..` comment. Keep one layout per class per unit; every row of the unit then matches first try.
- Do not invent member names for the inserted span; types/names of reached members from `pdb_types.py class`.
- One shift per class: the first row's delta predicts the class's other rows (all units that include it).
- Mirror case (T5.c2, DiskArbitrator::Update): a retail class that shrank (DiskQueue 0x84 -> 0x7C); same recipe, drop the removed span, retail offsets.
