# Filter plus backstop: give each its own teeth; mutate via --tool copies

Problem: a tool that drops bad items (name_sites --apply dropping DISABLED VAs) and also refuses before the write if
one remains: a control that only plants a bad item shows the drop, never the refusal (the drop hides it).

Move (5.4 T1.c2): keep the drop (`drop_disabled`) and the write-time refusal as two separate checks; the control
plants a bad item (dropped and reported), then patches the drop out at runtime so the refusal is seen to fire (rc 2,
file unchanged). For a relaxing verifier change (recut_cmp M33), the bad cases need mutations to show teeth: a
mutated copy (admit any def target / any lost reloc) placed in tools/ temporarily (the tool finds REPO from its own
path) and run through the control's `--tool PATH`; then each new rule switched off alone must fail its own positive.
Delete the copies after.

Replay of an old apply when its derived inputs are gone: rebuild pre-state and proposals from git blobs
(`git show <commit>:<path>`), run the real apply path, compare non-comment lines (what the cut reads).
