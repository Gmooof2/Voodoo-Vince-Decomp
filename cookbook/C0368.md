# Tool-written proof that lets a locked-file commit skip a review stop

Context: 5.3 T2.c2 (I48, R211, M32). A re-cut rewrites config/delink_cut.sha256 and the lock fingerprint; the hook
admitted those only under a `review: yes` task.

Technique:
- `tools/recut_proof.py write --pair PRE CUR [--adds U..] [--pair ..] --pins-pre <pre pin copy>` runs recut_cmp per pair
  and the gate, and writes config/recut_proof.json only when all are clean: hashes of the two LISTED files, per-pair
  summaries, gate line, tool sha256s, a seal over the body.
- githooks/commit-msg (not review: yes) calls `recut_proof.py check --staged`: hashes against the STAGED blobs
  (`git show :path`), verifier.sha256 differing from HEAD only on the delink_cut line, seal and tool hashes current,
  recut_cmp RE-RUN on the recorded pairs (so the pre copies must still exist at commit), gate last.json fp equal.
- recut_cmp `relocs-added` (M32) needs `--pins-pre`: an added reloc passes only at a newly pinned (VA, name), bytes
  equal outside the 4-byte field, old relocs unchanged, field VA (nearest resolvable anchor symbol) outside every
  matched_set function [va, va+size); unresolvable anchor -> refused.

Traps:
- autocrlf=true and no text attribute: `git add` stores LF; hash a text LISTED file as its staged (LF) form, or a clean
  proof refuses on a CRLF checkout (C0052). `-text` files hash as-is.
- `--adds` binds to the pair before it: a global --adds fails on relink section folders (it matches nothing there).
- Test the hook end to end in a scratch `git worktree` (own index), never the shared index.
