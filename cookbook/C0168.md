# C0168 — Cast removal by compile trial: obj same means no code from the line; rerun under /DNON_MATCHING
tags: cast,trial,compile,non_matching,readability,msvc,census · date: 2026-10-30 · phase/task: 3.6/T9 · origin: T9 scratch trial

Use: check many casts (or any single-token construct) for "is it needed?" before spending gate rounds.

- Scratch copy of `src` under `.run/<phase>/`, absolute paths (`msvc71.compile_one` fails C1083 on the relative include otherwise). Remove one cast by its column on the masked line (`readability_census.mask`, `pl.CAST` with the census's own filters), compile that unit with `build.flags_of`, compare the obj with the unit's baseline; zero COFF timestamp bytes 4..8 first. About 100 compiles fit one 285 s call.
- Three results: compile error (the cast is required, C2440, C2664, C2036, C2100, C2039, or C4717 when removal makes the function call itself), obj differs (meaning changed, e.g. `(const char*)this + off` becomes `this + off`, which still compiles), obj same.
- Obj same is mostly a trap: the line gave the unit no code. Code under `#ifdef NON_MATCHING`, an unused inline, an uninstantiated template all come back same, even `((Critter*)_node)->x` with the cast gone, which cannot compile. Rerun those rows with `/DNON_MATCHING` added to the flags: 38 same fell to 6 in 3.6 T9, and of those one was `(void*)false` (a null pointer constant) and four were zlib C `void*` conversions.
- A compile trial backs a reason; it is never match evidence, only the gate is.

Traps: the census CAST regex skips two-word pointer types (`const unsigned int*`, `struct x *`); grep them separately. A bash heredoc holding code with apostrophes broke once in this harness; write scripts with the Write tool.
