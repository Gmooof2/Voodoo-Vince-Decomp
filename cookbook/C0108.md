# C0108 — Ghidra no ref for pointer imm32/disp32: add USER_DEFINED DATA refs so the delinker relocates
tags: ghidra,delink,relocation,applysymbols · date: 2026-10-27 · phase/task: 3.2/T4 · origin: T4.c1 9b742cd9

# Ghidra makes no reference for pointer immediates whose register is not dereferenced

Symptom: a pinned site (call-site target or data pointer) has no relocation in the delinked object, though the
bytes at the site are an absolute VA of a named function/data. Typical forms: `mov r32, imm32` (B8..BF) whose
register is only pushed or passed, `push imm32`, `lea r,[r*4+disp32]` table bases.

Mechanism: Ghidra's analysis creates a memory reference only when it infers the operand is an address it uses;
the delinker emits a DIR32 only where Ghidra has a reference. No reference, no relocation, so the object's
bytes match but the site is unrelocated (link-time wrong address).

Fix (3.2 T4.c1, tools/ghidra_scripts/ApplySymbols.java): after symbols are applied, walk every instruction of
executable blocks; for each operand Scalar whose u32 value equals the exact VA of a func/data line and the
instruction has no reference to it, `addMemoryReference(ins, to, RefType.DATA, SourceType.USER_DEFINED, op)`.
Only exact table VAs (>= image base) qualify, so only imm32/disp32 can match. Summary field
`scalarRefs data D func F`. Retail: 10683 data + 37 func operands; gate unchanged green.

Check: `name_sites.py --check-cut` walks every pinned site and FAILs one with no relocation at its offset.
Risk: an immediate that equals a table VA by coincidence becomes a relocation; the gate's byte equality
still holds (the relocation resolves to the same VA), so only relink placement could expose it.
