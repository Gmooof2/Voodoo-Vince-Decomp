# C0166 — Sweep comments across a tree: decisions as a frozen table, code-part proof, dry run on a copy
tags: comments,sweep,verify,readability,provenance,batches · date: 2026-10-30 · phase/task: 3.6/T7 · origin: T7 expert, c1 batches

Sweep comments across a whole tree in two stages: judgement first, the edit-gate loop after. Dump every line the census counts into a table keyed by file, line and text, and read the normalised shapes rather than every line (2560 lines came to 1190 shapes). Default to remove; list what stays, by file and line, as data in one script. The script applies a batch only if each line still equals the table, so a tree that moved refuses (`stale`) instead of editing the wrong line.

Run the script on a copy first, with the static tools pointed at the copy: `provenance_lint --src`, `readability_census --src`, `annotations --check --src`. On 3.6 T7 that dry run showed lint PASS and every remaining line in a list, and all ten gated batches then passed first time.

Proof. C0165 drops `//`-only lines, so it cannot see trailing comments. Here compare, per file, the code part of every line: `line[:len(masked.rstrip())]`, with `readability_census.mask` blanking comments and keeping columns. Old blob against new tree must be identical, string contents included. Also compare the `// !FAKE:` lines, since `fake-diff` only looks at lines that start with that form.

Traps:
- A comment on a `field_<hex>` declaration cannot simply go: the lint's `placeholder` check needs `// 0x<hex>` on that line. Cut back to the offset instead.
- A line that continues a `!FAKE` or `best:` label is free text to the census. Removing a `!FAKE` continuation breaks the label; a `best:` head needs rewriting to one complete line once its continuation goes.
- `// NAME: proto-pdb:default.pdb (...)` must be cut back to the tag, never removed.
- `// src proto-pdb:default.pdb <name>` captures the next token, so `Name:` fails to resolve; write `<name> base X at 0x0`.
- `pdb.resolves` shows a name exists, not that the comment is true: read `pdb_types.py class|enum` for the claim too.
- `commit_task.sh` stages any untracked file under `logs/`, so a progress note can land in a coder's first commit.
