# Read-only XBDM client with a guarded single send path and a loopback mock

Use: any read of the dev's Xbox over XBDM (TCP 731) that must stay read-only (D75) and keep game bytes off disk (D46).
Reference: `tools/xbdm_probe.py` (1.7 T4).

- One `send(cmd)` is the only socket path; `guard()` runs before the lazy connect and before any byte: host in the
  configured `xbox_ip` (exactly one for commands), verb in an allow list (getmem, modules, modsections, dmversion),
  no CR/LF/NUL/non-ASCII (blocks `getmem ...\r\nsetmem ...` injection). Inject the socket factory so the self-test
  proves refusals with a recording socket (bytes written unchanged; factory never called for a bad host).
- Discovery among candidate addresses: connect, read the greeting line (`201- connected`, 200- on old builds), close,
  send nothing. Name candidates by index only in output.
- Wire (R1.7-003, R1.7-004; unconfirmed on a box until 1.7 T5): replies `<3 digits>- text`; 202 multiline ends with a
  line `.`; `getmem addr=0x%08X length=0x%X` body is 2 hex chars/byte, any line length, either case, `??` unreadable;
  chunk at <= 0x400; 404 not mapped, 407 unknown command (old builds lack `dmversion`), 402/403 no such module.
  `modules` lines `name="x" base= size= ...`; `modsections name="x"` lines `name= base= size= [index= flags=]`.
- Rehearse offline: a 127.0.0.1 mock maps the XBE in memory (headers at baseAddr from file[0:sizeOfHeaders],
  sections at virtualAddr zero-padded to virtualSize, else 404) and speaks the same wire; tests use
  `xbe_info._synthetic()` (its section data is all zeros: fill a copy with a pattern or a control read finds no
  differing block).
- Static-code residency proof: header known-true (`XBEH` at base, InitFlags at base+0x124), module base/size and
  section table equal, target sha1 equals file and body_sha1, and a same-length control address with different file
  bytes must mismatch.
