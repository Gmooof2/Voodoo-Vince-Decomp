# One marker per run: an inherited env note for child processes (5.4 T21)

Problem: a marked heavy step (timing.step(marker=)) starts children that are themselves marked steps (batch finish -> gate; public_walk -> clone gate/relink/build). Each would write its own marker, and a child in another folder (the walk's clone: project = clone folder name) reads the parent's marker as another project's load.

Move: the step that writes the marker sets `os.environ["TIMING_MARKER_HOLDER"] = f"{pid}|{project}"` for its block and pops it in finally (only if it set it). Children inherit it through any `dict(os.environ, ...)` copy. Under the note a step writes no marker and its reader skips the holder's project too. Nested in-process steps follow the same rule. No pid-ancestry walk needed; stdlib only.

Controls (scratch TIMING_MARKERS, never the shared folder): parent `python -c` step(marker=) runs a child `timing.py run` with cwd outside git and `GIT_CEILING_DIRECTORIES=<scratch>` so the child's project differs; expect one marker (parent's) during, child overlap [], none after. Second: a child step(marker=) under the note writes none. Self-test pops any inherited note first so it runs the same under a marked caller. Prove each control by reverting its guard on a scratch copy: only that control fails.

Traps: under core.autocrlf=true, Python write_text on Windows writes CRLF and verifier_lock refuses CRLF in LISTED files; `-text` files then show whole-file diffs. Edit by bytes or the Edit tool. A git stash/checkout re-writes CRLF into non-`-text` LISTED files, breaking the lock at HEAD until set back to LF. A LISTED re-pin moves the golden's fp line; when the phase golden predates other commits, record a scratch golden at HEAD (edits stashed) and check against it to prove fp-only, then re-record.
