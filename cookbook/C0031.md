# cl 13.10 big switch fn match: inline accessor tell, jump-table relocs, string/global names, /EH per obj

Context: MSVC 7.1 (cl 13.10.3077), 1.4 T9.c4, VinceDropsInCutscene::SetState (1732 B, 12-case jump table inside the proc, 89 calls).

- `this` loaded at a different point than retail (after the arg pushes instead of before): suspect an inline accessor
  (`g->GetX()->Load(...)` vs `g->_x->Load(...)`); look for the method name in the PDB class field list beside the field.
- Jump table: the obj's `$L<n>` case labels and the table operand are statics of the function's own section with a
  nonzero value; byte_compare resolves them as function VA + (value - function value) when inside the extent (T9 change).
  Don't name `$L<n>` in a table: compiler-internal numbers.
- `coff_info.DYN` `_<8 hex>` suffix rule needs a leading letter: C/C++ data symbols start with `_` or `?`, so it never fires
  for them. Reference retail strings as `extern "C" const char s_<va>[]` and add `_s_<va>` rows (address only, D46) to a
  hand-kept table (`config/retail/symbols_pin.txt`).
- /EH is per object: here no /EH (no EH frame despite basic_string temporaries); EvilVince.obj needed /EHa (C0030).
- /G5-/G7, /Ob2, /GS gave the same bytes; /Ob0 and /O2 change them; /Oy -> /Oy- is a strong control (1690 B diff).
