# Progress denominators: one population for bytes and counts; doubtful buckets follow the section

- Population: the post-ApplySymbols Ghidra export (`derived/ghidra/retail-<sha8>/applied/functions.jsonl`) when present. It is a strict superset of the T5 pre-apply bodies (checked 1.5 T7: 0 pre-only entries, 0 pre-only bytes; +701 functions, +69,048 B). Pre-apply bodies leave ApplySymbols-created functions (e.g. a matched fn at 0x000A871D) in "non-function", so a matched fn would sit outside the denominator.
- Labels (xbsymdb/xtlid) still come from the T5 pre-apply `symbols.jsonl`: ApplySymbols' USER_DEFINED renames drop those tags.
- Function count: class each function by the bucket class of its entry byte (xdk_report `functions.jsonl`), so counts and bytes share one classifier.
- Doubtful buckets (mixed, unidentified) count toward game iff their section's dominant class is game. That errs toward a larger denominator, so the percentage understates (D9, R0-027).
- Guard the numerator: every done row's va must be a counted entry, and its size must equal the objdiff ReportItem size. Reconcile counted + excluded + non-function == exec section total, else exit 1.
- Tools: `PY tools/xdk_report.py`, then `PY tools/progress.py [--self-test]`; docs/ops/tools.md `## progress`.
