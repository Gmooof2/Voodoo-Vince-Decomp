# Pipeline control: stop-before makes the does-not-fail-first run cheap

Problem: a control that proves an early check stops a long pipeline (public_walk: ingest, delink, xdk_report,
relink_cut ~6 min, gate, self-test) must first be shown DID NOT FAIL on the unfixed order (C0036). Running the
unfixed walk to the end costs a full walk.

Move (5.4 T1.c1): give the driver `--stop-before STEP` (prints `reached STEP`, rc 0) and a control subcommand
(`public_walk.py walk-ctl`) that plants the fault in the clone (moved aside, restored in `finally`), starts at the
step before the new check (`walk xdk_report --stop-before relink_cut`) and wants `STOP at <new step>`. Unfixed:
`reached relink_cut` = did not fail, in seconds; fixed: STOP at the early step.

Trap: a clone's gitignored `config/local_paths.json` is written at clone time; after a drive move (F: -> J:) it
still points at the old drive and the first step reading inputs refuses (rc 2). Rebuild it with clone()'s own rule
(public_walk.py clone section), never by hand-editing values in.
