# Teeth for a parallel map and a process lock in gate controls

- Parallel map (thread pool over unique keys): submit into a dict `{key: future}` and read `{k: f.result()}` by key; never zip keys with `as_completed`. A control plants one unit (one key) and asserts only that key's rows fail and every other row passes. The serial code is already right, so teeth come from a TEMPORARY mutation (verdicts rotated by one key) that must make the control print `DID NOT FAIL`; revert and diff empty (5.1 T2: the fail landed on EvilVince rows).
- Run lock (msvcrt LK_NBLCK on byte 1<<40, C0178) taken only in `main()`, so in-process library calls (the self-test's run() and `_core` controls) are never refused by their own lock.
- Its control (direct): a child `sys.executable` script holds the lock on a scratch path and signals; monkeypatch the module's lock path + `run` with a call-counting stub; `main([])` must be rc 2, refusal printed, stub not called; kill+wait the child, `main([])` rc 0 (OS dropped it: no stale lock); with `controls`/`_positive_ok` stubbed too, `main(["--self-test"])` rc 0. On the unfixed tree the same control prints DID NOT FAIL (main calls the stub), so no mutation is needed.
- A verdict-equality proof for a refactor: run `check()` from `git show HEAD:<file>` loaded as a scratch module against the new one on the real tree, json-dump both sorted, compare (5.1 T2: 1777 keys identical).
