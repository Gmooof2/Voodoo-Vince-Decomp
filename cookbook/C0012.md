# Toolchain of an MSVC 7.1 exe: Rich counts vs PDB compile records

When: deciding the compiler, linker and /GL of a VC 7.x exe that has its PDB (T11, phase 1.2).

- Count `S_COMPILE2` records per language (`pdb_info.py <pdb> --json`, `compile.language`, `fe/be`) and set them
  against the Rich entries (`pe_info.py <exe>`): Utc1310_C (0x5f) count == c records, Utc1310_CPP (0x60) == c++,
  Masm 7.1 (0x0f) == masm. Exact agreement makes two independent records for the cl build.
- Link build has three sources: Rich Linker (0x5a), PE optional header linker version, DBI `PdbDllVersion`.
- /GL has two signals: fLTCG (bit 10) in the compile records, and Utc1310_LTCG_C/CPP (0x63/0x64) in Rich (R1.2-006).
  Both are proven only on cl 19.x (fixture: fLTCG 1, Rich 0x104 -> 0x108). On 13.10 their absence is `inferred`.
- VC 7.1 `S_COMPILE2` has no strings after the version string (no command line), so /O and other switches are
  unknown from the PDB. Only the flag bits (noDbgInfo, securityChecks, ...) and `machine` are readable.
- Prodid 0x0c build 7291 (AliasObj60, VS6 OLDNAMES) pairs with OLDNAMES modules that have no symbol stream.
- `llvm-pdbutil dump --modi=N --symbols` (LLVM 23.1.3) segfaults on VC 7.1 module streams: use `pdb_info`.
